오늘 트렌딩은 에이전트를 개별 도구가 아니라 '조직'과 '방법론' 단위로 다루는 흐름이 두드러지는 하루입니다. 여러 에이전트를 마치 회사처럼 조직해 예산·승인·평가까지 관리하는 오케스트레이션 플랫폼(Paperclip)이 가장 큰 화제를 모았고, 어제에 이어 에이전트 기억 시스템(hindsight)과 오피스 문서 SDK(univer)도 스타가 계속 붙으며 자리를 지켰습니다. 여기에 코딩 에이전트에게 개발 방법론 자체를 스킬로 심어주는 두 프로젝트(mattpocock/skills, obra/superpowers)가 나란히 상위권에 오르면서, "에이전트에게 무엇을 시킬지"를 넘어 "에이전트를 어떻게 조직하고 어떤 습관을 갖게 할지"가 요즘 트렌딩을 관통하는 질문이라는 인상을 줍니다.

## paperclipai/paperclip

- <https://github.com/paperclipai/paperclip>
- 언어: TypeScript
- 오늘 스타: 1,853 (총 83,848)

여러 명의 자율 에이전트를 개별 도구가 아니라 "회사 조직"처럼 운영하게 해주는 오케스트레이션 플랫폼으로, Node.js 서버와 React UI 위에 조직도(org chart)·역할·권한 개념을 얹어 사람과 에이전트가 섞인 팀의 거버넌스를 관리합니다. 에이전트별 월 예산과 한도 도달 시 자동 스로틀링, 실행 전 승인과 감사 로그를 남기는 거버넌스 워크플로, 일정·이벤트에 맞춰 깨어나 작업을 확인하는 하트비트 실행 구조를 갖췄고, Claude Code·Codex 등 여러 에이전트 프로바이더를 플러그인으로 붙일 수 있게 설계했습니다. PostgreSQL을 기본 내장 저장소로 쓰면서도 완전한 데이터 격리를 보장하는 멀티 조직 지원까지 갖춰, 여러 에이전트를 프로덕션에서 안전하게 굴리려 할 때 필요한 예산·승인·관측 가능성 같은 운영 단위를 어떻게 추상화하는지 참고하기 좋습니다.

## vectorize-io/hindsight

- <https://github.com/vectorize-io/hindsight>
- 언어: Python
- 오늘 스타: 1,652 (총 28,761)

단순 대화 기록 검색을 넘어 에이전트가 시간이 지나며 스스로 학습하도록 설계된 메모리 플랫폼으로, 어제에 이어 오늘도 큰 폭으로 스타가 늘며 상위권을 지켰습니다. 사실·경험을 저장하는 Retain, 시맨틱·키워드·그래프·시간 축 검색을 병렬로 수행하는 Recall, 패턴을 종합해 새 통찰을 만드는 Reflect 세 연산을 중심으로 세계 사실과 에이전트 경험을 증거 기반 관찰과 정신 모델로 계층화해 저장하며, PostgreSQL+pgvector를 저장소로 25개 이상 LLM 프로바이더와 Python·Node.js·Go 클라이언트를 지원합니다. RAG나 지식 그래프가 놓치기 쉬운 "에이전트가 겪은 일에서 배우는" 구조를 어떤 자료구조와 연산으로 설계했는지 참고하기 좋은 프로젝트입니다.

## dream-num/univer

- <https://github.com/dream-num/univer>
- 언어: TypeScript
- 오늘 스타: 1,048 (총 18,196)

스프레드시트·문서·프레젠테이션을 완성된 뷰어가 아니라 필요한 기능만 골라 조립하는 컴포저블 오피스 SDK로, 어제에 이어 오늘도 스타가 크게 붙었습니다. 캔버스 기반 렌더링 엔진과 전용 수식 엔진, 플러그인 우선 아키텍처를 브라우저·Node.js 모두에서 동작하는 아이소모픽 설계 위에 React 18·TypeScript로 구현했고, 문서 타입마다 통일된 Facade API를 제공해 에이전트가 프로그램적으로 셀을 편집하고 결과를 검증할 수 있게 설계한 점을 앞세웁니다. 오피스 문서를 다루는 에이전트 워크플로가 늘어나는 흐름과 맞물려 채택이 이어지는 것으로 보이며, 헤드리스 문서 처리 엔진을 캔버스 렌더링과 어떻게 분리 설계하는지 볼 만합니다.

## mattpocock/skills

- <https://github.com/mattpocock/skills>
- 언어: Shell
- 오늘 스타: 671 (총 269,499)

실무 소프트웨어 엔지니어링에서 반복되는 실패 패턴(요구사항 불일치, 장황한 코드, 아키텍처 붕괴)을 겨냥한 재사용 가능 에이전트 스킬 모음으로, 사람이 직접 호출하는 오케스트레이션 스킬(`/grill-me`, `/to-spec`, `/implement`)과 모델이 알아서 불러 쓰는 규율형 스킬(`/tdd`, `/diagnosing-bugs`, `/code-review`)을 나눠 구성한 점이 특징입니다. `npx skills@latest`로 설치하거나 Claude Code 플러그인으로 바로 쓸 수 있게 만들었고, 여러 코딩 에이전트·모델에 이식 가능한 조합성을 강조합니다. 도메인 용어 공유, 피드백 루프, 의도적인 아키텍처 투자 같은 엔지니어링 원칙을 스킬 단위로 어떻게 쪼개 담았는지 참고할 만합니다.

- 언어: Shell
- 오늘 스타: 465 (총 291,488)

"코딩 에이전트를 위한 완전한 소프트웨어 개발 방법론"을 표방하며, 브레인스토밍부터 git worktree 격리, 2~5분 단위로 쪼갠 계획 수립, RED-GREEN-REFACTOR TDD, 코드 리뷰, 병합까지 개발 전 과정을 20개 이상 조합 가능한 스킬로 구현했습니다. 세션 시작이나 컨텍스트 컴팩션 이후 자동으로 스킬을 트리거하는 훅 시스템과 Claude Code·Cursor·Devin·Gemini CLI 등 15개 이상 에이전트에서 동작하는 플러그인 지원, 스킬 자체를 테스트하는 별도 평가 하네스(`superpowers-evals`)까지 갖췄습니다. 오늘 함께 오른 mattpocock/skills와 마찬가지로, 총 스타 29만 개가 넘는 규모는 "에이전트가 스스로 체계적으로 일하도록 절차를 스킬로 주입한다"는 접근이 얼마나 폭넓게 받아들여지는지 보여줍니다.

### SamuelSupe/RustDB

- <https://github.com/SamuelSupe/RustDB>
- 언어: Rust · 스타: 31 · 생성: 2026년 6월 이후

CSV·Parquet·S3/MinIO 데이터를 옮기지 않고 그 자리에서 분석하는 것을 목표로 내건 단일 노드 임베디드 OLAP 엔진으로, SQL 파싱 → 바인딩 → 최적화 → 물리 파이프라인 → Arrow RecordBatch로 이어지는 벡터화 실행 흐름 위에 Scan·Filter·Projection 연산자를 퓨전하고 Aggregate·Join·Sort·Window에서만 파이프라인을 끊는 구조를 갖췄습니다. unsafe Rust를 전면 금지하면서도 프로젝션·Parquet 페이지 인덱스 프루닝 같은 컬럼형 최적화와 스냅샷 격리 트랜잭션을 지원하고, TPC-H 22개 쿼리와 ClickBench 100만 행 프로필의 43개 쿼리를 전부 통과시켰다고 문서에 명시해두었습니다. v0.9 알파 단계이며 직렬화 가능 격리·인덱스 같은 기능은 아직 범위 밖이라고 스스로 밝히는 등, 벡터화 쿼리 엔진을 처음부터 설계하면서 어디까지 구현했고 무엇을 남겨뒀는지 투명하게 공개하는 점이 인상적입니다.

### exasol-labs/lakehouse-engine-rs

- <https://github.com/exasol-labs/lakehouse-engine-rs>

Iceberg·Delta Lake 위에 있는 데이터를 별도로 옮기거나 복제하지 않고 SQL로 직접 조회할 수 있게 해주는 Exasol용 인플레이스 쿼리 엔진으로, Exasol Labs가 직접 운영하는 프로덕션 지향 프로젝트입니다.
