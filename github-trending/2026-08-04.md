오늘 트렌딩 상위권은 어제와 겹치는 얼굴이 많습니다. 팀 단위 에이전트 메모리 시스템(TencentDB-Agent-Memory), 보안 리서치 도구 라우팅 프레임워크(reverse-skill), OCR 없는 PDF 파서(pdf-inspector)가 이틀 연속 자리를 지키는 가운데, Uber가 MLSys 2026에 발표한 에이전트 전용 침해 탐지·대응 플랫폼(ADR)과 코딩 에이전트에게 설계·계획·구현·리뷰 전 과정을 강제하는 방법론 프레임워크(superpowers)가 새로 상위권에 진입했습니다. "에이전트가 무엇을 하도록 둘 것인가"에서 한 걸음 나아가 "에이전트를 어떻게 감시하고 어떤 절차를 강제할 것인가"로 관심이 옮겨가는 흐름이 오늘 트렌딩 전반에서 뚜렷하게 읽힙니다.

## TencentCloud/TencentDB-Agent-Memory

- <https://github.com/TencentCloud/TencentDB-Agent-Memory>
- 언어: TypeScript
- 오늘 스타: 1,138 (총 13,044)

대화·문서·코드를 Chat Memory, Skills, Wiki, CodeGraph 네 가지 재사용 가능한 자산으로 정제해 여러 에이전트가 세션 너머로 경험을 공유하도록 만드는 팀 단위 메모리 관리 시스템으로, 어제에 이어 오늘도 상위권을 지켰습니다. 원본 대화(L0)를 비동기 파이프라인으로 원자 단위(L1)·시나리오(L2)·페르소나(L3)까지 층위를 나누고, ACL 기반 "로드아웃" 단위로 에이전트마다 접근 가능한 자산을 제한하는 구조가 핵심입니다. 이틀 연속 스타가 1,000개 이상 붙는 것을 보면, 단순 로그 저장을 넘어선 거버넌스형 에이전트 메모리 설계에 대한 수요가 일회성 화제가 아니라는 것을 보여줍니다.

## zhaoxuya520/reverse-skill

- <https://github.com/zhaoxuya520/reverse-skill>
- 언어: PowerShell
- 오늘 스타: 2,310 (총 17,401)

Claude Code, Cursor, Cline 같은 코딩 에이전트가 리버스 엔지니어링·모의 침투 작업을 할 때 jadx, IDA Pro, Frida, radare2, Ghidra 중 무엇을 언제 써야 하는지 결정 트리로 안내하는 라우팅 프레임워크입니다. 어제 총 스타 15,209에서 오늘 17,401로 하루 만에 다시 2,300개 넘게 늘면서 트렌딩 2위 자리를 지켰고, MASTER-ROUTING.md 게이트로 범위 확인·승인 없이 에이전트가 바로 실행에 들어가지 못하게 막는 구조가 여전히 핵심입니다. 위험도 높은 보안 작업에 에이전트를 투입할 때 도구 선택과 권한을 어떻게 중앙에서 통제할지 참고하기 좋습니다.

## firecrawl/pdf-inspector

- <https://github.com/firecrawl/pdf-inspector>
- 언어: Rust
- 오늘 스타: 2,524 (총 9,500)

OCR 없이 PDF가 텍스트 기반인지 스캔본인지 분류하고, 위치 정보를 유지한 채 텍스트를 깨끗한 Markdown으로 바꿔주는 Rust 라이브러리로, 어제보다도 더 많은 스타가 붙으며 오늘 트렌딩 전체에서 가장 큰 폭으로 성장했습니다. 콘텐츠 스트림의 텍스트·이미지 연산자를 세어 10~50ms 만에 문서 유형을 분류하고, 이후 폰트 분석·컬럼 자동 감지·읽기 순서 판별로 제목과 표까지 인식하는 구조입니다. 200개 PDF 벤치마크에서 다른 파서들을 앞섰다고 밝힌 점과 Python·Node·WASM 바인딩까지 갖춘 점이 이틀째 상승세를 뒷받침하는 것으로 보입니다.

## uber/ADR

- <https://github.com/uber/ADR>
- 언어: Python
- 오늘 스타: 140 (총 575)

Uber가 내부 코딩 에이전트(Cursor, Claude Code 등)와 대고객 AI 서비스를 함께 감시하기 위해 만들어 MLSys 2026에 발표한 에이전트 전용 탐지·대응 플랫폼입니다. 관측(7종 이상의 코딩 툴에서 의도·도구 사용·실행 트레이스 수집) → 벤치마킹(303개 태스크, 133개 MCP 서버, 17가지 에이전트 공격 기법 커버리지) → 탐지(고재현율 1차 스크리닝과 심층 추론을 결합한 2단계 구조) → 차단(오픈소스에는 미포함)의 4단계 파이프라인으로 설계돼 있습니다. 실제 프로덕션에서 돌리는 대기업이 에이전트 보안을 관측·벤치마크·탐지까지 구조적으로 쪼개 공개했다는 점에서, 오늘 함께 오른 reverse-skill(도구 라우팅으로 위험을 사전 차단)과 대비해 "이미 실행된 에이전트 행동을 어떻게 사후 탐지할 것인가"를 보여주는 사례입니다.

## obra/superpowers

- <https://github.com/obra/superpowers>
- 언어: Shell
- 오늘 스타: 617 (총 266,202)

코딩 에이전트에게 브레인스토밍(소크라테스식 질문으로 스펙 추출) → 계획(2~5분 단위 작업으로 분해, 정확한 파일 경로와 검증 단계 명시) → 구현(태스크마다 새 서브에이전트를 붙이고 스펙 준수·코드 품질 2단계 리뷰) → 테스트(RED-GREEN-REFACTOR TDD)까지 전체 개발 절차를 강제하는 재사용 가능한 스킬 라이브러리 프레임워크입니다. 누적 26만 개가 넘는 스타가 이미 붙어 있을 만큼 널리 퍼져 있으면서도, git worktree로 병렬 작업을 격리하고 YAGNI·DRY 원칙을 절차 전반에 못박아 에이전트가 장시간 무감독으로 정해진 계획을 벗어나지 않게 만드는 구조가 특징입니다. 11개 이상의 코딩 에이전트를 지원한다고 밝히고 있어, "에이전트에게 무엇을 시킬지"가 아니라 "에이전트가 일하는 절차 자체를 어떻게 표준화할지"를 보여주는 사례로 참고할 만합니다.

### tbit-bdd/JustLang

- <https://github.com/tbit-bdd/JustLang>
- 언어: C
- 스타: 7
- 생성일: 2026-07-16

단일 파일 C 구현(`just.c`/`just.h`)으로 만든 임베더블 스크립팅 언어로, JavaScript·Python과 비슷한 문법에 클로저와 구조화된 에러 처리, 설정 가능한 임계값을 가진 mark-and-sweep 추적 GC를 직접 구현하고 있습니다. 파일·네트워크·실행·플러그인·DB 접근을 개별적으로 켜고 끌 수 있는 capability 기반 샌드박싱과 반복 횟수·호출 깊이·토큰 수 제한까지 갖춰, 신뢰할 수 없는 스크립트를 안전하게 실행하는 것을 명시적 목표로 삼고 있습니다. 100개 넘는 내장 함수를 13개 카테고리로 정리한 API 문서, SQLite·mbedTLS를 빌드 타임에 선택적으로 링크하는 네 가지 빌드 변형까지 문서화돼 있어, 테스트 스위트가 눈에 띄지 않는다는 한계는 있지만 GC와 샌드박싱을 처음부터 설계한 인터프리터 구현체를 공부하기 좋은 프로젝트입니다.

### deathbyknowledge/ripgit

- <https://github.com/deathbyknowledge/ripgit>
- 언어: Rust
- 스타: 150
- 생성일: 2026-03-18

Cloudflare Durable Objects 위에 얹은 self-hosted Git 원격 저장소로, 레포 하나당 Durable Object 인스턴스 하나를 붙여 `git push`/`clone`/`fetch` 같은 표준 Git 연산을 서버 없이 처리합니다. 각 Durable Object는 최대 10GB SQLite에 11개 테이블과 FTS5 가상 테이블 3개를 두어 전문 검색을 지원하고, xpatch 델타 압축으로 파일 변경 빈도에 따라 5~20배 압축률을 낸다고 밝히고 있습니다. Durable Object의 10초 실행 제한이나 요청 본문 100MB 제한 같은 플랫폼 한계를 README에 구체적으로 명시하고 체크포인트 단위 증분 푸시 같은 우회책까지 제시하는 점, 4만 개 넘는 커밋을 가진 실제 레포로 라이브 데모를 돌리고 있는 점에서, 서버리스 오브젝트 위에 Git 프로토콜을 어떻게 재구현하는지 구체적으로 살펴볼 수 있는 사례입니다.

### traverse-framework/traverse

- <https://github.com/traverse-framework/traverse>
- 언어: Rust
- 스타: 135
- 생성일: 2026-03-26

한 번 작성한 비즈니스 로직을 브라우저·서버·클라우드에서 동일하게 실행하기 위한 Rust 런타임 프레임워크로, 모든 capability가 지켜야 할 동작을 불변 contract 파일로 정의해 실행 전에 검증하는 "contract-driven" 구조가 핵심입니다. 이식 가능한 capability는 `wasm32-wasi`로 컴파일돼 결정적으로 실행되며, 런타임 엔진·contract 파서·CLI·MCP 서버까지 8개의 크레이트로 역할을 나눈 구조입니다. 핵심 로직에 100% 테스트 커버리지를 강제하고 87개의 불변 스펙으로 런타임·contract·레지스트리·WASM·네이티브 임베딩 영역을 통제하며, 리눅스·macOS·윈도우 5개 플랫폼 CI 매트릭스와 PR마다 공급망 검증 게이트를 돌린다고 밝히고 있어, 스펙 기반 거버넌스를 실제 배포된 레지스트리(v0.8.1)까지 이어붙인 구체적인 사례로 참고할 만합니다.

### Awesome-Embedded-Learning-Studio/Cinux-Book

- <https://github.com/Awesome-Embedded-Learning-Studio/Cinux-Book>
- 언어: C++
- 스타: 48
- 생성일: 2026-03-22

x86_64 운영체제를 처음부터 끝까지 만들어보는 튜토리얼이자 그 결과물 자체인 "Cinux" 프로젝트의 안정판입니다. 리얼 모드에서 프로텍티드 모드를 거쳐 롱 모드로 가는 부트로더, 미니 커널에서 풀 커널로 확장하는 2단계 커널 개발, 22개 시스템 콜을 가진 링3 유저 모드, VFS로 감싼 Ext2 읽기/쓰기와 SATA/AHCI 드라이버, 캔버스 렌더링 기반 GUI 데스크톱까지 OS 스택 전 계층을 다룹니다. 표준 라이브러리 없이 `constexpr`과 `concepts` 같은 C++17 기능으로 컴파일 타임 디스크립터를 생성하고 RAII로 자원을 관리하는 구현 방식, 호스트 측 모킹과 QEMU 통합 테스트를 함께 두는 이중 테스트 전략, 개발 여정을 그대로 보여주는 42개의 git 태그까지 갖추고 있어, 이론이 아니라 실제로 부팅되는 코드로 OS 각 계층을 배우고 싶을 때 참고하기 좋습니다.
