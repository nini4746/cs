오늘 트렌딩은 에이전트 생태계를 구성하는 여러 층위가 한꺼번에 상위권에 오른 하루입니다. 에이전트에게 구직 활동 전체를 맡기는 프레임워크(ai-job-search), 에이전트를 보안 감사관으로 바꾸는 스킬(security-audit-skill), 여러 코딩 에이전트를 동시에 지휘하는 데스크톱 오케스트레이터(orca), 그리고 에이전트가 코드를 적게 쓰도록 강제하는 프롬프트 스킬(ponytail)까지 — "에이전트에게 무엇을 시키고, 어떻게 감독하고, 어떻게 덜 쓰게 할 것인가"라는 질문이 네 가지 다른 각도에서 동시에 다뤄지고 있습니다. 그 사이에서 ComfyUI처럼 이미 성숙한 생성 AI 워크플로 도구가 여전히 꾸준히 스타를 모으는 것도 눈에 띕니다.

- 언어: Python
- 오늘 스타: 3,890 (총 59.6k)

Claude Code 위에서 돌아가는 구직 자동화 프레임워크로, 채용 공고 스크래핑부터 적합도 평가, CV·커버레터 작성(LaTeX/moderncv 컴파일), 인터뷰 준비, 결과 추적까지 구직의 전 과정을 슬래시 커맨드로 엮었습니다. `/apply` 과정에서 한 에이전트가 초안을 쓰고 맥락이 분리된 다른 에이전트가 비평한 뒤 다시 수정하는 "작성자-리뷰어" 패턴을 쓰는 점이 특징이며, 채용 공고를 신뢰할 수 없는 입력으로 간주해 방어적으로 다룬다는 보안 설명도 README에 명시돼 있습니다. 개인정보가 추적 파일에 그대로 쓰이기 때문에 공개 저장소 포크 대신 비공개 저장소에서 이 레포를 upstream으로 쓰라고 권고하는 부분은, 에이전트에게 민감한 개인 데이터를 맡길 때의 운영상 주의점을 구체적으로 보여줍니다.

## cloudflare/security-audit-skill

- <https://github.com/cloudflare/security-audit-skill>
- 언어: JavaScript
- 오늘 스타: 849 (총 33.4k)

코딩 에이전트를 보안 감사관으로 바꾸는 스킬로, 정찰(아키텍처·신뢰 경계 매핑) → 커버리지 기반 탐색 → 후보 검증 → 구조화된 출력 → 독립 재검증 → 보고의 6단계 파이프라인을 프롬프트와 Node.js 검증 스크립트로 구현했습니다. 핵심은 "찾아낸 취약점을 또 다른 독립된 에이전트가 반증을 시도"하는 적대적 검증 구조와, `confirmed`/`needs_validation`/`rejected`를 명확히 구분하는 판정 기준입니다. 같은 저장소를 반복 실행하면 누적된 커버리지 원장(coverage ledger)을 재사용해 한 번 실행으로는 전체 취약점의 절반 정도만 찾아낸다는 README의 실측치는, 에이전트 기반 보안 감사에서 "반복 실행"이 왜 구조적으로 필요한지를 보여줍니다.

## stablyai/orca

- <https://github.com/stablyai/orca>
- 언어: TypeScript
- 오늘 스타: 1,559 (총 99.3k)

Claude Code, Codex, OpenCode 등 약 25개 이상의 CLI 에이전트를 각각 독립된 git worktree에서 동시에 돌리고 결과를 비교·병합할 수 있는 데스크톱 오케스트레이터입니다. 같은 프롬프트를 여러 에이전트에 동시에 보내 결과를 나란히 비교하는 병렬 worktree 구조, 모바일 앱으로 진행 상황을 확인하고 후속 지시를 보내는 기능, AI가 만든 diff에 줄 단위로 코멘트를 남겨 되돌려주는 리뷰 도구까지 갖추고 있어, "에이전트 한 대"가 아니라 "에이전트 함대"를 운영하는 작업 단위가 실제 제품으로 자리잡고 있음을 보여주는 사례입니다. Electron·Vite·pnpm 워크스페이스 기반의 구조도 여러 에이전트의 터미널·브라우저·SSH 세션을 한 화면에서 관리하는 UI를 어떻게 설계하는지 참고할 만합니다.

AI 코딩 에이전트가 코드를 쓰기 전에 "이 기능이 정말 필요한가 → 이미 코드베이스에 있는가 → 표준 라이브러리로 되는가 → 이미 설치된 의존성으로 되는가"라는 7단계 사다리를 거치도록 강제하는 프롬프트 스킬입니다. 핵심 구현은 `skills/ponytail/SKILL.md` 하나의 마크다운 프롬프트뿐이고, 나머지는 Claude Code 플러그인·Cursor rules·Codex 플러그인 등 각 호스트에 맞게 같은 프롬프트를 포장한 디렉터리 구조입니다. Opus 5.5로 39개 과제를 5회씩 돌려 코드량 53%, 비용 26% 감소와 위험 로직 테스트 커버리지 98%(스킬 미적용 시 68%)를 보고하는 자체 벤치마크가 있는데, 자기 보고 수치라는 한계는 있지만 "스킬 파일만으로 에이전트의 코딩 습관 자체를 바꾼다"는 접근을 수치로 검증하려 한 시도라는 점이 눈에 띕니다.

### dom96/KillSwitch

- 언어: Rust
- 스타: 102

LLM이 생성하거나 수정하기 어렵도록 의도적으로 설계된 난해한 프로그래밍 언어(esoteric language)로, Rust로 작성된 레퍼런스 인터프리터와 `cargo test`로 돌아가는 테스트, 언어 명세를 담은 `SPEC.md`, LLM들의 벤치마크 성적을 공개 추적하는 사이트(bench.killswitch-lang.org)까지 갖추고 있습니다.
