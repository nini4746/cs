### cetrafs/cetrafs

- <https://github.com/cetrafs/cetrafs>
- 언어: C
- 스타: 47, 생성일: 2026-10-22

여러 노드가 iSCSI나 Fibre Channel로 연결된 같은 블록 디바이스(LUN)를 동시에 마운트하는 클러스터형 공유 디스크 파일시스템으로, VMFS의 대안을 표방합니다. 핵심은 네트워크가 아니라 스토리지 자체로 노드 간 합의를 보는 설계인데, 네임스페이스 락이나 Zone Group 소유권 같은 모든 경쟁 자원을 512바이트 레코드 단위의 원자적 SCSI COMPARE AND WRITE(CAW)로 잠그고 각 노드는 자신의 Zone Group에서만 블록을 할당해 충돌을 피합니다. 노드 생존은 하트비트와 120초 기본 타임아웃으로 판단하고 죽은 것으로 간주된 노드는 스스로를 펜싱해 입출력 오류를 반환하며, 재마운트 시 리두 저널을 재생하고 모든 온디스크 구조에 CRC32C를 걸어 읽기 시점에 검증합니다. 루프백 이미지로 돌리는 `make check`, 교차 노드 경로까지 실제 하드웨어에서 검증하는 두 노드 전용 스위트, 크래시·퍼징 테스트까지 갖추면서도 "pre-1.0" 단계임을 스스로 명시하고 지원 커널·엔디안을 좁게 한정해둔 점에서, 분산 락과 저널링을 블록 디바이스 레벨에서 어떻게 설계하는지 공부하기 좋은 레포입니다.

### itay-insert/64-dem

- <https://github.com/itay-insert/64-dem>
- 언어: C++
- 스타: 42, 생성일: 2026-06-27

UEFI와 레거시 BIOS 양쪽에서 부팅되는 취미용 64비트 x86-64 운영체제로, 커널뿐 아니라 부트로더 전체를 바닥부터 구현했습니다. UEFI 경로는 GOP로 최고 해상도를 잡고 자체 ELF 파서로 커널을 읽어 적재하는 반면, BIOS 경로는 440바이트 1단계 부트섹터의 FAT32 파서부터 2단계, 16비트 3단계, 32비트 C로 쓴 4단계까지 이어지는 체인으로 보호 모드 진입과 A20 활성화, BIOS 메모리 맵을 UEFI 호환 형식으로 바꾸는 작업까지 직접 처리합니다. 커널은 1GB를 2MiB 페이지로 매핑하는 4단계 페이지 테이블을 부트로더가 먼저 구성해 롱 모드로 진입시킨 뒤, 비트맵 프레임 할당자로 자체 페이징을 다시 구축하고 커널과 프레임버퍼를 상위 절반(higher-half)으로 재매핑하는 과정을 거칩니다. 트랩을 걸어 한 단계씩 실행을 추적할 수 있는 비주얼 디버거 스크립트를 UEFI·BIOS 경로 각각에 마련해두고, 실제 하드웨어 6종에서의 부팅 성공과 QEMU에서 재현되지 않았던 BIOS 경로 버그까지 README에 솔직하게 적어둔 점에서, 부트로더 단계별 권한 전환과 페이징 전환을 눈으로 따라가며 공부하기 좋은 자료입니다.

### mustafaahci/goz

- <https://github.com/mustafaahci/goz>
- 언어: Rust
- 스타: 49, 생성일: 2026-07-16

Windows NTFS 볼륨에서 voidtools Everything을 대체하려는 초고속 파일 검색 엔진으로, MFT(Master File Table)를 직접 읽어 한 번의 패스로 전체 파일명을 인덱싱하고 NTFS USN 저널을 테일링해 실시간으로 색인을 갱신합니다. 코어(파싱·인덱스·질의 엔진)를 OS에 무관한 순수 크레이트로 분리하고 얇은 unsafe Win32 레이어, 권한 상승된 인덱싱 데몬(`gozd.exe`)과 일반 권한 CLI 클라이언트(`goz.exe`)로 나눈 4-크레이트 워크스페이스 구조를 택했으며, 질의 결과는 16바이트 참조로만 들고 다니다가 페이지 단위로 경로를 조립해 검색 중에도 인덱스 압축·증분이 끊기지 않게 만들었다고 설명합니다(최장 검색 지연을 29ms에서 1.6ms로 줄였다는 수치까지 공개). Everything 1.4.1과 같은 조건에서 비교한 벤치마크로 파일 출력 기준 1.8~6.1배, 파이프 기준 2.3~3.5배 빠르고 유휴 메모리는 12MB 대 369MB라고 보고하면서도, 원시 MFT 읽기라 파일별 ACL을 건너뛴다는 점과 콘텐츠 검색이 IFilter 없이 평문만 찾는다는 한계를 README가 스스로 밝히는 점에서, 파일시스템 메타데이터를 저수준으로 인덱싱하는 설계와 성능 트레이드오프를 함께 공부하기 좋은 레포입니다.
