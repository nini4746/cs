오늘 트렌딩 상위권은 어제와 거의 똑같은 다섯 레포가 그대로 자리를 지킨 하루입니다. Claude-BugHunter, superpowers, CLI-Anything, minimind, cursor/plugins가 순서까지 동일하게 이틀 연속 1~5위를 차지했는데, 이는 "에이전트에게 보안 점검·개발 방법론·CLI 도구·에디터 확장까지 맡긴다"는 흐름이 하루짜리 화제가 아니라 꾸준히 관심을 받는 주제라는 뜻으로 읽힙니다. 오늘의 히든잼에서는 반대로 에이전트 바깥, 컴파일러와 인터프리터를 직접 밑바닥부터 짜보는 개인 프로젝트들을 모아봤습니다.

## 오늘의 히든잼

### mi-vault/mibicc

- <https://github.com/mi-vault/mibicc>
- 언어: C
- 생성일: 2026-11-17 (스타 29)

x86-64 Linux와 Windows를 모두 타깃으로 하는 교육용 C 컴파일러로, 표준 헤더만 쓰는 순수 C99로 작성되었습니다. 토크나이저 → 재귀 하향 파서(AST) → 스택 머신 코드 생성기 → `as`/`gcc`/`clang`으로 어셈블·링크하는 전형적인 파이프라인을 단계별로 쌓아가며, 로드맵의 1~10단계(정수 연산, 변수, `if`/`while`/`for`, 블록문)까지는 체크를 마쳤고 함수 호출·포인터·배열·구조체·자기 호스팅은 아직 열려 있는 과제로 남겨뒀습니다. `make test`로 돌리는 테스트와 GitHub Actions CI 배지, 그리고 설계 결정과 삽질 과정을 기록한 `DEVLOG.md`까지 갖춰, 컴파일러를 처음부터 짜볼 때 어떤 순서로 단계를 쌓아야 하는지 참고하기 좋은 프로젝트입니다.

### liustack/beastjs

- <https://github.com/liustack/beastjs>
- 언어: Go (코드 생성 산출물 비중 때문에 GitHub 통계상 Assembly로 표시됨)
- 생성일: 2026-10-13 (스타 54)

순수 Go로 서버사이드 React 렌더링을 위한 JavaScript 엔진을 만든 프로젝트로, Fabrice Bellard의 QuickJS를 LLVM으로 컴파일해 Go 어셈블리로 통째로 저장소에 체크인해두는 독특한 구조를 취합니다. `CGO_ENABLED=0`만으로 빌드가 끝나고, 체크인된 어셈블리가 생성기 출력과 다르면 `make check-gen`이 실패하도록 만들어 수작업 수정이 섞여 들어갈 수 없게 막아뒀습니다. Go 1.26.6~1.27 전 패치 릴리스에 대해 매주 어셈블리를 재검증하고, test262 표준 적합성 테스트에서 실패 33건(업스트림 수정 반영 전보다 25건 감소)까지 공개하며, C 코드는 AddressSanitizer·UndefinedBehaviorSanitizer로 따로 검증합니다. 외부 엔진을 가져와 자동 생성 파이프라인으로 재검증하고 유지보수하는 방식 자체가, 바닥부터 새로 짜는 것만큼이나 진지한 엔지니어링 사례로 읽힙니다.

### QuartzProject/Quartz

- <https://github.com/QuartzProject/Quartz>
- 언어: C++
- 생성일: 2026-11-19 (스타 18)

호스트 애플리케이션(게임 서버, 에디터 플러그인 등) 안에서 신뢰할 수 없는 코드를 돌리기 위한, 정적 타입의 샌드박스 임베딩 언어입니다. 연료(fuel)·메모리 할당량·재귀 깊이 제한이 항상 켜져 있고, 모든 모듈이 실행 전에 IR 검증기를 통과해야 하며, 레지스터 기반 인터프리터와 LLVM 네이티브 컴파일 티어를 함께 제공하면서도 정수 래핑과 엄격한 IEEE 754 부동소수점으로 두 실행 경로의 결과가 플랫폼과 관계없이 동일하도록 설계했다고 밝힙니다. C++23/CMake/Ninja로 빌드되고 C/C++ API는 물론 JVM(Java/Kotlin)과 Kotlin Multiplatform, WebAssembly 바인딩까지 갖췄으며, Ryzen 7 5800X 단일 코어에서 C(Clang -O2)·Lua·Luau·Wren·AngelScript와 나란히 비교한 벤치마크 표를 공개해 네이티브 티어가 일부 워크로드에서 C에 근접한 성능을 낸다고 보여줍니다. 아직 초기 개발 단계임을 스스로 명시하면서도 보안 정책 문서와 매 커밋 자동 릴리스 체계를 갖춰, 샌드박스 스크립트 언어를 설계할 때 결정론과 성능을 어떻게 동시에 추구하는지 볼 수 있는 프로젝트입니다.

### zmlsaggg/Leksika

- <https://github.com/zmlsaggg/Leksika>
- 언어: C
- 생성일: 2026-11-10 (스타 15)

러시아어 키워드와 격변화 문법, 키릴 문자 구문을 쓰는 실험적 프로그래밍 언어(Лексика)입니다. 데스크톱 엔진은 Python으로 돌아가지만, 네이티브 코어는 C11로 작성되어 레지스터 기반 바이트코드로 컴파일한 뒤 가상머신에서 실행하며, 컴파일 결과를 CRC32 검증이 붙은 `.lekb` 포맷 1.0 바이너리 모듈로 저장할 수도 있습니다. `make test`, 네이티브 엔진 비교 스크립트, Node.js 어댑터 테스트 등 여러 진입점의 테스트 스위트를 여러 플랫폼에서 GitHub Actions로 돌린다고 밝히고 있고, 네이티브 코어가 아직 언어 전체를 지원하지 못한다거나 Android 앱이 입력을 못 받는다는 한계도 README에 솔직하게 적어뒀습니다. 스타 수는 적지만 장난감 언어에 머물지 않고 자체 바이트코드·VM·바이너리 모듈 포맷까지 갖춘, 완성도에 공을 들인 개인 언어 프로젝트입니다.
