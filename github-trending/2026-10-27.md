오늘 트렌딩은 "에이전트에게 코드 실행을 넘어 취향과 작업 방식 자체를 맡기는" 흐름이 다시 상위권을 채운 하루입니다. 디자인 스킬 hallmark와 impeccable이 나란히 올라 "AI 티 나는 디자인"을 어떻게 걸러낼지를 계속 다투고 있고, 로컬 데스크톱에서 여러 에이전트 CLI를 워크스페이스 단위로 관리하는 openbot과 cindy가 함께 상위권에 자리했습니다. 여기에 obra/superpowers처럼 스펙 작성부터 TDD, 코드 리뷰까지 에이전트의 작업 절차 자체를 스킬로 패키징한 "소프트웨어 개발 방법론" 레포가 끼어든 것을 보면, 단순히 결과물의 품질을 다듬는 단계를 넘어 에이전트가 일하는 순서와 습관까지 표준화하려는 시도가 폭넓게 진행되고 있는 모습입니다.

- 오늘 스타: 2,859 (총 38.3k)

## nightly-labs/openbot

- <https://github.com/nightly-labs/openbot>
- 언어: TypeScript
- 오늘 스타: 794 (총 약 2.0k)

로컬 우선 데스크톱 앱으로, Codex·Claude Code·Grok CLI·OpenCode·Gemini·Cursor CLI·Cline CLI 같은 로컬 에이전트 CLI를 각각 독립된 작업 공간에 담아 영속적으로 돌립니다. Electron 메인 프로세스가 Codex와는 stdio JSONL로, Claude와는 Agent SDK의 스트림 JSON으로 통신하고 나머지는 ACP로 연결하며, SQLite 이벤트 로그와 TanStack Start 기반 계정 서비스, WebRTC 데이터채널로 팀 간 공유까지 갖춘 구조입니다. 다만 아직 개발 프리뷰 단계라 에이전트가 파일·명령·네트워크·브라우저에 확인 절차 없이 접근한다고 스스로 밝히고 있어, 여러 하네스를 한 데스크톱에 모을 때 권한 모델을 어떻게 설계할지 고민해볼 만한 사례입니다.

### palemorrow/mordant

선언적 syscall 규칙을 Linux seccomp용 classic BPF(cBPF) 프로그램으로 컴파일하는 정책 컴파일러로, C11로 구현하면서 컴파일러 모델 자체를 Agda로 형식 명세해 둔 프로젝트입니다. 정책 파일이 파서 → 타입이 있는 IR → 로워링 → 분기 배치 → 검증을 거쳐 커널의 4096 명령어 제한을 넘지 않는 `sock_filter[]` 배열로 바뀌고, x32 syscall 번호는 거부하며 아키텍처 불일치 시 `kill_process`로 안전하게 실패하도록 설계했습니다. README가 Agda 증명과 C 구현 사이의 간극을 `make diff` 차분 테스트로 메운다고 명시하고, 커널 통합 테스트와 유닛 테스트, 타입체킹을 각각 분리된 Makefile 타깃으로 두고 있는 것을 보면, 작은 규모(12 스타, 11 커밋)에도 형식 검증과 실제 구현을 잇는 절차를 꼼꼼히 갖춘 프로젝트입니다.
