Anthropic이 직접 운영하는 Claude Code 플러그인 마켓플레이스(claude-plugins-official)와 Cursor의 플러그인 저장소(cursor/plugins)가 나란히 올라와 각 진영이 자체 플러그인 생태계를 공식화하는 흐름을 보여주고, 그 위에서는 opencode 같은 오픈소스 코딩 에이전트와 ruflo 같은 멀티 에이전트 오케스트레이션 하네스가 "에이전트를 어떻게 조합하고 제어할 것인가"를 두고 경쟁하고 있습니다. 여기에 Claude Code를 포크해 구직 과정 전체를 자동화한 ai-job-search까지 겹치면서, 에이전트가 코드를 짜는 도구를 넘어 "생태계 플랫폼"과 "개인 워크플로 자동화"라는 두 방향으로 동시에 확장되는 모습이 뚜렷합니다.

## anthropics/claude-plugins-official

- 언어: Python
- 오늘 스타: 1,187 (총 42,366)

Anthropic이 직접 큐레이션하는 Claude Code 플러그인 마켓플레이스입니다. 내부 플러그인은 `/plugins`, 외부 파트너·커뮤니티 플러그인은 심사를 거쳐 `/external_plugins`에 들어가는 구조이고, 각 플러그인은 `plugin.json` 매니페스트에 커맨드·에이전트·MCP 서버·스킬을 선언합니다. 한 번 공개된 마켓플레이스 `name`은 바꿀 수 없고 표시용 `displayName`과 `renames` 맵으로만 이름을 조정하게 한 점, `SKILL.md`만 있는 저장소를 `strict: false`로 등록하는 방식 등에서 "플러그인 생태계를 깨지지 않게 운영하는 법"을 구체적으로 볼 수 있습니다.

구 Claude Flow였던 프로젝트로, Claude Code와 Codex를 감싸 멀티 에이전트 조율·영속 메모리·에이전트 간 통신을 더해주는 TypeScript/Rust 하네스입니다. 벡터DB 기반 메모리(AgentDB, HNSW)로 작업 결과를 학습하고, 서로 다른 머신의 에이전트가 mTLS와 ed25519로 신원을 확인하며 통신하는 "federation" 기능, MCP 서버로 자신의 도구를 노출하는 구조가 특징입니다. 단일 작업에는 강하지만 에이전트 간 조율이나 세션을 넘어선 학습이 약한 Claude Code류 도구의 공백을 정면으로 노리는 프로젝트라, 에이전트 오케스트레이션 레이어를 어떻게 얹을지 고민할 때 참고할 만합니다.

### wkoszek/emuko

- <https://github.com/wkoszek/emuko>

RV64IMAFDC와 M/S/U 권한 레벨, Sv39 가상 메모리까지 구현해 Linux를 부팅시키는 RISC-V 에뮬레이터입니다. ARM64/x86_64용 JIT와 인터프리터를 백엔드로 선택할 수 있고, UART 16550·CLINT·PLIC·SBI 1.0 같은 주변장치와 전체 머신 상태 스냅샷 저장/복원, QEMU `virt` 플랫폼과 호환되는 메모리 맵까지 갖추고 있습니다. README에 Linux 부팅과 베어메탈 ELF 부팅 각각의 메모리 레이아웃 다이어그램, QEMU·Spike·Renode와의 성능 비교표, "JIT 모드가 QEMU보다 29배 느리다"는 한계까지 솔직하게 적어 둔 점에서 문서 품질이 높습니다. JIT-인터프리터 간 결과를 맞대 보는 차등 검증 체계도 갖추고 있어, 바닥부터 CPU 에뮬레이터를 쌓아 올리는 과정을 공부하기 좋은 레포입니다.

### dweinstein/canary

- <https://github.com/dweinstein/canary>
- 언어: Go / 스타: 95 / 생성일: 2026-03-24

macOS용 파일시스템 허니팟으로, `.env`나 `id_rsa` 같은 가짜 비밀 파일을 가상 디렉터리로 마운트해 두고 누군가 건드리면 알림을 보냅니다. WebDAV 프로토콜 핸들러로 사용자 권한에서 동작하는 모드와, FUSE 없이 NFSv3 프로토콜을 직접 구현해 root 권한으로 동작하는 모드 두 가지를 제공하며, 실제 파일은 디스크에 전혀 쓰지 않고 서버가 떠 있는 동안만 가상 파일트리가 존재합니다. Go 표준 라이브러리만 써서 약 1,400줄, 8MB 바이너리로 완성했고, 두 모드의 보안 트레이드오프 비교표와 launchd 설정까지 README에 담아 둔 점이 돋보입니다. NFS 와이어 프로토콜을 직접 손으로 구현해 보는 예제로서, 그리고 "속지 않는 보안"을 가볍게 구현하는 설계로서 공부할 가치가 있습니다.

### 0xff-ai/omnifs

- <https://github.com/0xff-ai/omnifs>
- 언어: Rust / 스타: 87 / 생성일: 2026-04-12

GitHub, DNS, Docker, Kubernetes, SQLite 같은 외부 시스템을 로컬 파일 경로로 투영해 `cd`, `grep`, `jq` 같은 평범한 도구로 다룰 수 있게 해주는 가상 파일시스템입니다. 각 프로바이더를 `omnifs:provider` WIT 인터페이스를 구현하는 WebAssembly 컴포넌트로 만들어, 프로바이더는 토큰이나 소켓을 직접 들고 있지 않고 호스트 데몬에 타입이 있는 콜아웃(HTTP 요청, blob 다운로드 등)을 요청하는 구조로 권한을 분리한 점이 핵심 설계입니다. 파일시스템 프런트엔드는 Linux에서 FUSE, macOS에서 읽기 전용 NFSv4 루프백으로 붙고, npm으로 배포되는 CLI에 실시간 TUI 인스펙터까지 포함되어 있습니다. 아직 알파 단계라 자동화된 테스트는 보이지 않지만, "플러그인을 Wasm 컴포넌트로 격리하고 호스트가 권한을 중개한다"는 아키텍처 자체가 에이전트 시대의 샌드박싱 설계를 고민할 때 참고할 만합니다.
