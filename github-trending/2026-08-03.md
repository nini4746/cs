오늘 트렌딩은 "AI 에이전트를 실제로 돌리는 데 필요한 인프라"라는 주제로 묶입니다. 제한된 GPU 메모리에서 거대 모델을 굴리는 추론 엔진(airllm), 보안 리버싱 작업에 어떤 도구를 써야 할지 에이전트에게 알려주는 라우팅 프레임워크(reverse-skill), OCR 없이 문서를 파싱하는 라이브러리(pdf-inspector), 터미널에서 동작하는 코딩 에이전트(DeepSeek-Reasonix), 그리고 에이전트가 세션을 넘어 경험을 공유하도록 만드는 메모리 시스템(TencentDB-Agent-Memory)까지, 모델 자체보다 그 모델을 감싸는 실행·도구·기억 레이어에 대한 관심이 상위권 전반에 걸쳐 뚜렷합니다.

## lyogavin/airllm

- <https://github.com/lyogavin/airllm>
- 언어: Jupyter Notebook
- 오늘 스타: 1,081 (총 26,645)

70B급 모델을 4GB VRAM에서, 405B Llama 3.1은 8GB에서, 671B DeepSeek-V3는 약 12GB에서 돌릴 수 있게 해주는 추론 라이브러리입니다. 핵심은 레이어를 한 번에 하나씩만 GPU에 올리는 레이어별 스트리밍 방식이고, MoE 모델에서는 레이어 전체 대신 실제로 활성화된 전문가(expert)만 로드해 메모리를 더 아낍니다. 여기에 4비트·8비트 블록 단위 양자화(최대 3배 추론 속도 향상 보고)를 더해 Llama·Qwen·DeepSeek·Mistral 등 주요 오픈소스 모델 계열을 동일한 `AutoModel.from_pretrained()` API로 다룰 수 있게 해, 소비자용 하드웨어에서 대형 모델을 굴리기 위한 메모리 관리 기법을 종합적으로 살펴보기 좋은 프로젝트입니다.

MASTER-ROUTING.md 같은 마스터 라우팅 파일을 게이트로 두어, 범위 확인과 승인 없이 에이전트가 바로 실행에 들어가지 못하게 막는 구조가 특징입니다. ## firecrawl/pdf-inspector

- <https://github.com/firecrawl/pdf-inspector>
- 언어: Rust
- 오늘 스타: 1,769 (총 7,406)

OCR 없이 PDF가 텍스트 기반인지 스캔본인지 분류하고, 위치 정보를 유지한 채 텍스트를 추출해 깨끗한 Markdown으로 바꿔주는 Rust 라이브러리입니다. 콘텐츠 스트림을 샘플링해 Tj/TJ 같은 텍스트 연산자와 이미지 연산자를 세어 10~50ms 만에 네 가지 유형(텍스트 기반/스캔본/이미지 기반/혼합)으로 분류하고, 이후 폰트 분석·컬럼 자동 감지·읽기 순서 판별을 거쳐 폰트 크기 비율로 제목을, 표 그리기 연산자와 텍스트 정렬 휴리스틱으로 표를 인식합니다. 200개 PDF로 다른 파서들과 벤치마크해 전체 점수·읽기 순서 점수·처리 속도 모두 앞섰다고 밝히고 있고, Python·Node·브라우저 WASM 바인딩까지 갖추고 있어 문서 파싱 파이프라인을 로컬에서 빠르게 돌리고 싶을 때 참고하기 좋습니다.

## esengine/DeepSeek-Reasonix

- <https://github.com/esengine/DeepSeek-Reasonix>
- 언어: Go
- 오늘 스타: 877 (총 29,735)

DeepSeek 모델을 활용하는 터미널 기반 코딩 에이전트로, 단일 정적 Go 바이너리로 배포됩니다. 프로바이더·에이전트·툴·플러그인을 하드코딩하지 않고 `reasonix.toml` 설정 파일로 선언하는 구조이고, 실행기(executor)와 계획자(planner) 두 모델을 별도의 캐시-안정 세션으로 동시에 돌릴 수도 있습니다. 외부 도구는 stdio JSON-RPC(MCP 호환)로 통신하는 서브프로세스 플러그인으로 붙고, 장시간 세션에서 토큰 비용을 줄이기 위해 안정적인 환경 요약을 시작 시 주입하고 낡은 툴 출력을 컴팩션 전에 정리하는 프리픽스 캐시 최적화를 핵심으로 내세웁니다. CGO 비활성화로 6개 플랫폼에 의존성 없는 바이너리를 빌드하는 부분까지 포함해, 장시간 켜두고 쓰는 코딩 에이전트를 어떻게 비용 효율적으로 설계하는지 참고할 만합니다.

## TencentCloud/TencentDB-Agent-Memory

- <https://github.com/TencentCloud/TencentDB-Agent-Memory>
- 언어: TypeScript
- 오늘 스타: 1,091 (총 11,845)

대화·문서·코드를 Chat Memory, Skills, Wiki, CodeGraph 네 가지 재사용 가능한 메모리 자산으로 바꿔, 여러 에이전트와 프레임워크가 경험을 세션 너머로 공유하게 해주는 팀 단위 메모리 관리 시스템입니다. 원본 대화(L0)를 비동기 파이프라인으로 점점 정제해 원자 단위(L1)·시나리오(L2)·페르소나(L3)로 층위를 나누고, 모든 지식을 전역으로 주입하는 대신 ACL 기반 권한이 결합된 "로드아웃" 단위로 에이전트마다 접근 가능한 자산을 제한합니다. PersonaMem 벤치마크에서 59% 개선을 보고하고 기존 코드베이스·대화 이력을 가져오는 콜드 스타트까지 지원한다고 밝히고 있어, 단순 로그 저장을 넘어 거버넌스와 버전 관리, 역할별 선택적 공유까지 고려한 에이전트 메모리 설계 사례로 볼 만합니다.

### rustic-compiler/rustc_codegen_c

- 언어: Rust
- 오늘 스타: 92
- 생성일: 2026-04-07

Rust의 MIR(중간 표현)을 C 소스 코드로 트랜스파일한 뒤 gcc·clang 같은 표준 C 컴파일러로 최종 컴파일하는 실험적인 rustc 백엔드입니다. LLVM이 지원되지 않지만 C 컴파일러는 있는 플랫폼에서도 Rust를 컴파일할 수 있게 해주는 것이 목표로, 미리 빌드된 툴체인을 내려받거나 C 소스부터 빌드하거나 rustc 전체를 처음부터 컴파일하는 등 여러 진입 경로를 지원합니다. 이 백엔드로 빌드한 Rust 컴파일러가 rustc UI 테스트 스위트의 99.2%를 통과한다고 밝히고 있어, 트랜스파일 과정에서 Rust의 의미론적 보장이 상당히 잘 보존된다는 것을 실증적으로 보여줍니다. CPU 특화 명령어가 필요한 크레이트는 지원하지 않는다는 한계를 스스로 밝히면서도, 컴파일러 백엔드를 이식성 높은 C로 재타겟팅하는 접근을 구체적인 통과율로 검증한 사례입니다.

- 오늘 스타: 91
- 생성일: 2026-07-21

셰이더 컴파일러를 브라우저로 실어 나르는 대신, TypeScript로 작성한 `*.shader.ts` 파일을 미리 WGSL로 컴파일해두는 WebGPU 셰이더 프레임워크입니다. 빌드 단계에서 파싱·타입 체크·GPU 시맨틱 분석·중간 표현·최적화를 거쳐 완성된 WGSL과 타입 정보를 담은 `*.shader.gen.ts` 모듈을 생성하고, 런타임은 이 결과물을 그대로 쓰는 19KB(gzip 7KB)짜리 얇은 WebGPU 레이어만 남깁니다. 골든 파일로 컴파일러 출력 텍스트를 검증하는 Node 테스트와 Chrome·WebKit을 실제로 구동해 픽셀 출력을 확인하는 GPU 테스트를 함께 두면서도 Safari의 엄격한 WGSL 검증은 자동화할 수 없다는 한계를 README에 그대로 밝히고 있습니다. "컴파일은 한 번, 여러분의 개발 머신에서만 일어나고 브라우저는 완성된 셰이더 텍스트와 런타임만 받는다"는 설계 원칙이 컴파일 시점과 실행 시점을 얼마나 엄격히 분리할 수 있는지 보여주는 사례입니다.
