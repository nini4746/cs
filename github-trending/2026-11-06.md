Atom과 Tree-sitter를 만든 팀이 내놓은 고성능 멀티플레이어 코드 에디터로, "Code at the speed of thought"를 표방합니다. ## NVIDIA/auto-ontology

- <https://github.com/NVIDIA/auto-ontology>
- 언어: Python (TypeScript/FastAPI 혼합)
- 오늘 스타: 2,005 (총 8,508+)

엔터프라이즈 DB 스키마를 비즈니스 용어·검증된 SQL·테이블 관계로 압축한 "온톨로지"로 미리 만들어두는 컨텍스트 레이어로, 어제에 이어 이틀째 상위권을 지켰습니다. 작업 흐름을 생성(Generate: 스키마를 읽어 용어·조인·SQL 속성 초안을 Postgres에 기록)→검증(Certify: 사람이 초안을 다듬고 승인)→응답(Answer: 에이전트가 임베딩 검색으로 후보 용어를 찾아 SQL을 작성·검증·실행)의 3단계로 분리해 사람의 승인 단계를 구조적으로 끼워넣은 점이 특징이며, Apache Ossie YAML 모델 포맷으로의 가져오기·내보내기를 지원하고 예측형 질문은 선택적으로 외부 호스팅 서비스인 KumoRFM으로 라우팅할 수도 있습니다. 하루 사이 스타가 2천 개 넘게 더 늘며 여전히 가장 큰 관심을 받고 있는데, 검증된 중간 표현에 사람의 승인 단계를 명시적으로 끼워넣는 설계는 에이전트에게 DB 접근을 맡길 때 참고할 만한 패턴입니다.

## mpv-player/mpv

- <https://github.com/mpv-player/mpv>
- 언어: C
- 오늘 스타: 36 (총 37,792)

MPlayer를 기반으로 만든 커맨드라인 미디어 플레이어로, 다양한 포맷·코덱·자막을 지원합니다. Meson을 빌드 시스템으로 쓰고 디코딩은 FFmpeg, 렌더링은 고정 기능 GPU 파이프라인이 아니라 셰이더 기반으로 처리하며(`libplacebo`), 자막은 `libass`, 스크립팅은 선택적으로 Lua를 붙이는 구조입니다. 하드웨어 디코딩은 기본값이 아니라 `--hwdec`로 명시적으로 켜야 하고, 릴리스는 1년에 한두 번만 끊어서 최신 릴리스만 유지보수하는 보수적인 운영 방식을 쓰고 있습니다. 셰이더로 비디오 렌더링 파이프라인을 직접 구성하는 방식과, 느리더라도 안정적인 릴리스 주기를 유지하는 유지보수 전략 둘 다 참고할 만합니다.

Qwen3.5-2B의 가중치 안에 파일시스템 자체를 "컴파일"해 넣은 실험적 프로젝트입니다. residual 차원을 2048에서 4096으로 넓히고 학습되지 않은 8개의 파일시스템 레이어를 Qwen의 24개 레이어 앞에 덧붙여, attention 레이어로 파일 읽기(토큰 그대로 복사)·경로 해석·검색을 구현하고 Gated DeltaNet 상태로 버전·경로 테이블을 들고 있는 구조이며, 파일은 3바이트 토큰 ID로 압축해 디스크에 저장하고 세션이 시작되면 모델이 읽기 요청을 낼 때만 해당 파일을 페이징합니다. 10파일·128파일 세션에서 강제 토큰 6,300여 개를 전부 맞혔고, 병합된 모델이 Qwen 원래의 top-1 예측을 검증한 139개 위치 전부에서 그대로 유지했다는 수치까지 공개했으며, 파일당 용량 제한이나 대소문자 구분 완전일치 검색만 가능하다는 한계도 구체적으로 밝혔습니다. 모델 가중치 내부에 상태 머신을 직접 짜 넣는 기계적 해석 가능성(mechanistic interpretability) 실험으로서 공부할 거리가 많은 프로젝트입니다.
