오늘 트렌딩은 "코딩 에이전트를 어떻게 더 잘 쓰게 만들 것인가"라는 질문이 리뷰, 지식, 제어, 평가라는 서로 다른 층위에서 동시에 나타나는 하루입니다. 에이전트가 만든 계획과 diff를 사람이 검토하기 쉽게 만드는 로컬 리뷰 도구(plannotator), 에이전트에게 최신 웹 플랫폼 지식을 주입하는 스킬 모음(modern-web-guidance-src), 투자자를 위한 Claude Skills 토대(claude-trading-skills), 에이전트가 실제 브라우저를 제어하도록 돕는 MCP 서버(chrome-devtools-mcp), 그리고 에이전트의 코드 리뷰 결과를 더 정확하고 저렴하게 만들려는 하이브리드 시스템(open-code-review)까지, 다섯 레포 모두가 "에이전트 자체"보다는 "에이전트를 둘러싼 인프라"를 다루고 있다는 점이 눈에 띕니다.

## backnotprop/plannotator

- <https://github.com/backnotprop/plannotator>
- 언어: TypeScript
- 오늘 스타: 412 (총 10,765)

Claude Code, Codex, Gemini CLI 등 여러 코딩 에이전트의 plan mode와 PR/MR diff를 브라우저 UI에서 주석을 달아 되돌려줄 수 있게 만든 로컬 리뷰 도구입니다. 각 에이전트 하크니스의 훅을 통해 plan 제안을 가로채고, Git·GitButler·Jujutsu·Perforce diff 뷰어와 줄 단위 코멘트, 그리고 에이전트가 질문을 올리는 "Inbox" 창까지 Bun 기반 로컬 서버 하나로 제공합니다. 텔레메트리 없이 로컬에 머무른다는 점과 릴리스에 SLSA provenance, SBOM을 첨부하는 점을 보면, "에이전트와의 대화창"이 아니라 "에이전트 산출물을 검토하는 전용 화면"을 어떻게 설계하는지 참고하기 좋은 사례입니다.

- 오늘 스타: 1,225 (총 5,505)

- 언어: Python
- 오늘 스타: 556 (총 4,506)

시간이 부족한 개인 투자자를 위해 시장 점검, 리스크 관리, 트레이드 플래닝, 저널링을 구조화한 Claude Skills 모음입니다. README는 이 도구가 매수·매도를 대신 결정하지 않으며 신호 서비스나 자동매매 시스템이 아니라고 명시하고, 사람의 의사결정 게이트를 중심에 둔 "더 나은 판단 과정"을 위한 툴킷이라고 설명합니다. 각 스킬이 `SKILL.md`와 참고자료, 헬퍼 스크립트로 구성되고 YAML 워크플로 매니페스트가 이를 묶어주는 구조는, 금융처럼 리스크가 큰 도메인에서 에이전트에게 자율성을 어디까지 줄 것인지 설계할 때 참고할 만합니다.

알리바바 내부 코드 리뷰 어시스턴트를 오픈소스로 공개한 CLI로, 범용 에이전트가 큰 diff에서 파일을 건너뛰거나 줄 번호를 잘못 짚는 문제를 "순수 언어 기반 워크플로에는 하드 제약이 없기 때문"이라고 진단합니다. 해결책으로 파일 선택·리뷰 단위 묶기·룰 매칭·코멘트 위치 지정은 결정론적 엔지니어링 모듈이 맡고, 동적 판단과 컨텍스트 탐색만 LLM 에이전트에게 맡기는 하이브리드 구조를 택했습니다. 50개 오픈소스 저장소·200개 PR·1,505개 주석 이슈로 구성한 자체 벤치마크(AACR-Bench)에서 같은 모델의 Claude Code 리뷰보다 토큰을 9분의 1 가까이 줄이면서 정밀도를 높였다고 주장하는데, "LLM에 하드 제약을 어디까지 코드로 대신 걸어줄 것인가"를 구체적 수치로 보여주는 사례입니다.

### MARKJY-China/XuanTie-Lang

- <https://github.com/MARKJY-China/XuanTie-Lang>
- 언어: C / XuanTie(자체 언어)
- 스타: 108, 생성일: 2026-04-05

중국어 키워드를 쓰는 시스템 프로그래밍 언어로, Go로 쓴 "시드 컴파일러"로 부트스트랩한 뒤 컴파일러 자체(41,738줄의 `.xt` 소스 중 12,573줄)를 XuanTie로 다시 작성해 자기 자신을 컴파일하는 self-hosting 구조를 갖추고 있습니다. 백엔드는 LLVM IR을 생성하고 `mem2reg` 최적화를 거치며, 메모리 관리는 GC 없이 C11 `stdatomic.h` 기반의 원자적 참조 카운팅(ARC)으로 처리해 GC pause 자체를 없앴다고 설명합니다. lexer, parser, ast, evaluator, runtime, stdlib, LSP, IDE까지 구성 요소가 나뉘어 있고 릴리스마다 퍼징을 포함한 회귀 테스트를 돌린다고 밝히고 있어, 컴파일러 자기 호스팅과 GC-free 메모리 관리를 한 프로젝트에서 같이 들여다볼 수 있는 자료입니다. 다만 저자가 코드의 약 90%를 LLM으로 생성했다고 직접 밝히고 1.0 이전에는 작은 프로젝트에만 쓰라고 권고하는 점은 감안해야 합니다.

### nidheesh-m-vakharia/camus

- <https://github.com/nidheesh-m-vakharia/camus>
- 언어: Rust
- 스타: 29, 생성일: 2026-11-05

Apache Kafka 4.4.0과 와이어 프로토콜 호환을 내세우는, JVM과 ZooKeeper 없이 단일 Rust 바이너리로 뜨는 메시지 브로커입니다. 로그를 Cloudflare R2(혹은 S3 호환 스토리지)에 직접 저장하고 메타데이터와 짧은 WAL만 Raft로 복제하는 구조를 택했으며, `wal` 모드(샤드 과반수 fsync 후 ack)와 `r2` 모드(오브젝트 스토리지 커밋 후 ack)라는 두 가지 내구성 레벨을 명시적으로 분리해 제공합니다. CI에서 `cargo test --workspace`를 돌리는 것은 물론, 실제 리더를 죽였다가 새 쓰기가 커밋되는지 보는 클러스터 테스트와 진짜 Kafka Connect·Streams·MirrorMaker 2를 붙여보는 생태계 테스트까지 갖추고 있고, ADR 문서로 설계 결정을 남기며 R2 모드의 p99 지연이 10ms 미만 워크로드에는 맞지 않는다는 한계까지 README에 솔직히 적어둔 점에서 완성도가 높습니다. 분산 로그를 객체 스토리지에 올리는 설계와 Raft 기반 메타데이터 복제를 함께 공부하기 좋은 레포입니다.
