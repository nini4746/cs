오늘 GitHub 트렌딩은 "에이전트가 무엇을 대신 들여다볼 수 있는가"가 두 방향으로 동시에 벌어지는 하루입니다. 한쪽에서는 에이전트에게 바이너리 리버싱(REA)과 PS5 네이티브 포팅(AnyPS5)처럼 로우레벨 시스템 지식을 맡기려는 시도가 눈에 띄고, 다른 쪽에서는 에이전트 스킬 생태계 자체가 엔지니어링 워크플로(mattpocock/skills), 다이어그램 제작(diagram-design), 코드 리뷰(open-code-review)로 계속 세분화되며 깊어지고 있습니다. 특히 알리바바가 내부에서 2년간 수만 명에게 검증한 코드 리뷰 도구를 "결정론적 엔지니어링 + 에이전트"라는 하이브리드 구조로 공개한 점은, 범용 에이전트만으로는 한계가 있는 영역에서 전통적인 엔지니어링 기법을 다시 끌어오는 흐름을 보여줍니다.

## morluto/rea

- <https://github.com/morluto/rea>
- 언어: TypeScript
- 오늘 스타: 15,335 (총 37,830)

네이티브 바이너리, JavaScript/Electron 앱, .NET 어셈블리, 웹사이트까지 리버스 엔지니어링할 수 있도록 에이전트에 도구를 연결해주는 MCP 서버입니다. 네이티브 분석은 기존 Hopper나 Ghidra 설치를 활용하고(승인 시 Hopper를 자동 설치하는 옵션도 제공), 정적 JavaScript 분석은 별도 엔진 없이도 동작하는 구조가 특징입니다. 핵심은 "에이전트가 소스 코드 없이 기능을 조사하고, 증거와 한계를 함께 제시한 뒤, 그 결과로 자신의 프로젝트에 비슷한 기능을 구현하게 만든다"는 워크플로인데, Claude Code·Codex·Cursor 등 여러 에이전트에 공통으로 붙는 MCP 계층으로 "리버싱"이라는 전문 영역을 표준화하려는 시도로 볼 수 있습니다.

## boykopovar/AnyPS5

- <https://github.com/boykopovar/AnyPS5>
- 언어: C++
- 오늘 스타: 5,925 (총 19,869)

PS5 실행 파일을 Linux·Windows에서 네이티브로 돌리기 위한 포팅 도구로, 에뮬레이션이나 별도 런타임 프로세스 없이 실행 파일을 타겟 시스템의 네이티브 포맷으로 변환하는 relinker와, 동적 링킹에 필요한 PS5 시스템 prx 라이브러리들을 직접 재구현한 구현체로 구성됩니다. 셰이더 리컴파일러가 SPIR-V를 생성하고 Spirv-Tools로 검증까지 거치며, GTX 1050 Ti 같은 저사양 GPU에서도 2D 플랫포머가 안정적인 60fps로 동작한다고 검증 목록에서 밝히고 있습니다. 에뮬레이션 대신 "재링킹 + ABI 재구현"으로 접근한다는 점에서, Wine이 Windows 바이너리를 다루는 방식과 비교해보며 바이너리 포팅과 시스템 라이브러리 구현을 공부하기 좋은 프로젝트입니다.

## mattpocock/skills

- <https://github.com/mattpocock/skills>
- 언어: Shell
- 오늘 스타: 1,696 (총 282,183)

"바이브 코딩이 아니라 실제 엔지니어링"을 위해 만들었다고 밝히는 에이전트 스킬 모음으로, 매일 실무에서 쓰는 스킬들을 작고 조합 가능한 단위로 쪼개 공개했습니다. GSD·BMAD·Spec-Kit 같은 프로세스 전체를 떠맡는 접근과 달리 통제권을 사용자에게 남겨두면서 "에이전트가 내가 원하는 걸 하지 않는다"는 흔한 실패 모드(의도 불일치)를 다루는 데 초점을 맞춘 점이 특징입니다. Claude Code·Codex·Copilot·Gemini CLI 등 거의 모든 에이전트 환경에 설치 경로를 열어두고 6만 명 넘는 뉴스레터 구독자를 쌓아온 것을 보면, 개별 스킬 저장소를 넘어 "에이전트 작업 방식에 대한 방법론"으로 자리잡으려는 움직임으로 읽힙니다.

## cathrynlavery/diagram-design

- <https://github.com/cathrynlavery/diagram-design>
- 언어: HTML
- 오늘 스타: 1,744 (총 47,498)

에이전트가 만드는 다이어그램이 늘 비슷한 "둥근 사각형 뭉치"로 보이는 문제를 풀기 위한 Claude Code 스킬로, 빌드 과정이나 외부 이미지 의존성 없이 브라우저에서 바로 열리는 자체 완결 HTML+SVG로 아키텍처·플로차트·ER·타임라인·칸반·Wardley 맵 등 수십 종의 에디토리얼 품질 다이어그램을 만들어줍니다. "행동을 표현하는 시맨틱 패턴"과 "레이아웃"을 분리해 큐나 신뢰 경계 같은 개념이 새 다이어그램 타입을 늘리지 않고도 기존 타입에 얹히도록 설계했고, draw.io·Mermaid·Excalidraw로 만든 기존 다이어그램을 원하는 포맷·크기·디테일로 다시 그려주는 기능도 있습니다. "가장 좋은 선택은 보통 삭제다"라는 원칙 아래 노드 수와 강조색을 억제하는 디자인 철학을 스킬 파일에 코드화한 사례로, 올해 여러 번 트렌딩에 오른 디자인 스킬 흐름의 연장선에 있습니다.

## alibaba/open-code-review

- <https://github.com/alibaba/open-code-review>
- 언어: Go
- 오늘 스타: 323 (총 44,909)

알리바바 그룹 내부에서 2년간 수만 명의 개발자가 쓰며 수백만 건의 결함을 찾아낸 AI 코드 리뷰 CLI를 오픈소스로 공개한 프로젝트입니다. Git diff를 읽어 변경된 파일을 도구 사용이 가능한 에이전트에게 넘기고, 전체 파일 내용과 다른 변경 파일까지 참조하게 해 표면적인 diff 리뷰를 넘어서는 깊은 리뷰를 만드는데, 핵심은 "반드시 틀리면 안 되는 단계는 결정론적 엔지니어링이, 동적 판단이 필요한 단계는 에이전트가 맡는다"는 하이브리드 구조입니다. 파일을 정밀하게 선택·묶어 서브에이전트가 독립된 컨텍스트로 나눠 리뷰하게 하는 분할정복 전략, 별도의 코멘트 위치/반성(reflection) 모듈로 위치 정확도를 개선하는 설계가 특징이며, 50개 오픈소스 저장소·200개 PR·10개 언어로 구성한 자체 벤치마크(AACR-Bench)에서 범용 에이전트(Claude Code) 대비 토큰을 9분의 1만 쓰면서도 정밀도와 F1이 더 높다고 밝히고 있습니다. 다만 재현율은 더 낮다는 트레이드오프를 스스로 명시한 점도 참고할 만합니다.
