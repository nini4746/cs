오늘 트렌딩은 "에이전트에게 방법론과 취향까지 패키지로 넘긴다"는 흐름이 여러 각도에서 동시에 나타나는 하루입니다. JetBrains는 코딩 에이전트 `pi`를 감싸는 전용 IDE(thinkrail)를 내놓았고, superpowers는 설계·TDD·코드 리뷰까지 포함한 소프트웨어 개발 방법론 전체를 에이전트용 skill 묶음으로 만들었습니다. 여기에 디자인 감각을 skill로 넘기는 ai-design-skills, 튜터링·연구·퀴즈를 하나의 에이전트 워크스페이스로 묶은 DeepTutor, 이메일·문서·CRM을 에이전트가 동료처럼 편집하는 all-in-one 워크스페이스 macro까지 겹치면서, 에이전트에게 "어떻게 일할지"뿐 아니라 "무엇을 좋다고 여길지"까지 구조화해서 건네는 시도가 여러 영역에서 동시에 진행되고 있음을 보여줍니다.

## JetBrains/thinkrail

- <https://github.com/JetBrains/thinkrail>
- 언어: TypeScript
- 오늘 스타: 1,075 (총 4,692)

JetBrains가 내놓은 오픈소스(Apache 2.0) 인큐베이터 프로젝트로, 코딩 에이전트 `pi`를 감싸는 전용 IDE입니다. `pi`가 모델·skill·컨텍스트 압축·비용·세션 상태를 모두 책임지고, thinkrail은 워크스페이스·에디터·통신 계층만 담당하는 역할 분리가 핵심 설계입니다. 각 작업을 별도 git worktree로 분리해 여러 에이전트가 사용자의 체크아웃을 건드리지 않고 병렬로 작업하게 하고, 모듈마다 `SPEC.md`를 두어 에이전트가 "living spec"을 직접 유지하도록 한 점에서, 대기업이 에이전트 중심 개발 환경을 어떻게 구조화하는지 참고하기 좋은 사례입니다.

## elayadesign/ai-design-skills

- <https://github.com/elayadesign/ai-design-skills>
- 언어: Markdown
- 오늘 스타: 1,395 (총 10,730)

Claude Code, Cursor, Codex, Windsurf 같은 코딩 에이전트에게 쓸 수 있는 디자인 skill 모음으로, 코드가 아니라 `SKILL.md` 하나로 "취향"을 패키지화한 점이 특징입니다. 대표 skill인 `landing-page-design`은 인테이크 질문, 페이지 구조, 전환을 위한 카피, 타이포·여백·radius·모션 같은 비주얼 시스템까지 규정해두고, 디자인 값들을 한 섹션에 몰아넣어 포크 후 그 부분만 바꾸면 skill 전체의 결과물이 바뀌도록 설계했습니다. 오늘 함께 트렌딩에 오른 superpowers와 나란히 놓고 보면, "절차"뿐 아니라 "미적 기준"까지 마크다운 파일 하나로 에이전트에게 넘기는 방식이 빠르게 표준화되고 있다는 신호로 읽힙니다.

"작동하는 완전한 소프트웨어 개발 방법론"을 표방하며 총 스타 30만 개를 넘긴, 코딩 에이전트용 skill 프레임워크입니다. 브레인스토밍과 설계 승인, git worktree 기반 작업 분리, 문서화된 구현 계획, 서브에이전트 주도 개발, TDD, 2단계 코드 리뷰(스펙 준수 → 코드 품질), 브랜치 완료까지 전체 워크플로를 skill로 구성해두고 "강제되는 워크플로, 제안이 아니다"라고 명시한 점이 눈에 띕니다. Claude Code, Codex, Cursor, Gemini CLI 등 여러 에이전트 하네스를 지원하며, 세션에 문제가 생겼을 때 스스로 진단하는 skill까지 포함되어 있어, 에이전트에게 "무엇을 하라"가 아니라 "어떤 과정을 반드시 거쳐라"를 강제하는 설계를 살펴보기 좋은 프로젝트입니다.

## HKUDS/DeepTutor

- <https://github.com/HKUDS/DeepTutor>
- 언어: Python
- 오늘 스타: 2,376 (총 47,472)

튜터링, Q&A, 퀴즈 생성, 심층 리서치, 시각화, 숙련도 연습을 하나의 capability 런타임과 세션 컨텍스트 위에서 돌리는 "에이전트 네이티브 학습 워크스페이스"입니다. LlamaIndex, PageIndex, GraphRAG, LightRAG 등 여러 검색 엔진을 지식베이스 백엔드로 교체할 수 있고, 메모리를 벡터 스토어에 숨기는 대신 L1(원본 기록)·L2(표면적 사실)·L3(종합)의 3계층 파일로 구조화해 사람이 직접 읽고 수정·검증할 수 있게 만든 점이 핵심 설계입니다. CLI가 NDJSON 이벤트를 스트리밍해 다른 에이전트가 이를 조작할 수 있게 한 구조와, 관련 arXiv 프리프린트(2604.26962)까지 공개한 점에서, 학습 보조 에이전트의 메모리를 "감사 가능하게" 설계하는 방법을 공부하기 좋습니다.

- 오늘 스타: 106 (총 5,251)

이메일, 채팅, 문서, 작업, 캔버스, 에이전트, CRM을 하나로 묶은 "오픈 코어가 아니라 완전한 오픈소스(AGPLv3)" 팀 워크스페이스입니다. SolidJS와 Rust로 이루어진 모노레포(42개 서비스, 167개 Rust 라이브러리)가 하나의 백엔드를 공유하고, 항목 간 참조를 양방향 그래프로 저장하는 구조가 특징입니다. 문서 공동 편집은 Cloudflare Durable Objects 위의 CRDT로 처리하는데, 에이전트가 이 시스템 안에서 사람과 동등한 "peer"로 문서를 편집할 수 있게 설계했고, 매일 밤 대화·이메일·작업 기록에서 팀 단위 메모리를 합성해 MCP로 노출한다고 밝히고 있습니다. 에이전트를 협업 도구의 부가 기능이 아니라 1급 사용자로 취급하는 아키텍처를 들여다보기 좋은 사례입니다.

## 오늘의 히든잼

### manishrjain/egres

- <https://github.com/manishrjain/egres>
- 언어: Zig
- 스타: 142개 (생성일: 2026-02-06)

멀티테넌트 환경을 겨냥한 Postgres 호환 데이터베이스로, "Postgres 재작성이 아니라 처음부터 다시 설계한 것"이라고 README에서 밝히는 Zig 프로젝트입니다. Postgres의 와이어 프로토콜을 그대로 구현해 `psql`이 수정 없이 붙게 하면서도, jemalloc을 빌드 시점에 내려받아 쓰고 Postgres의 파서·압축 라이브러리를 Zig의 C 툴체인으로 직접 벤더링해 gcc·clang 없이 빌드되게 만든 점이 특징입니다. 단위 테스트(`zig build test`), 실서버를 띄워 pgwire로 검증하는 e2e 스크립트, main 푸시마다 돌아가는 pre-push 게이트까지 갖춰 개인 프로젝트치고 CI 체계가 탄탄하고, 코드 대부분을 AI 에이전트로 작성했지만 모든 코드 경로를 직접 리뷰했다고 밝힌 개발 과정도 눈에 띕니다.

### ybouane/flashraw

- 언어: Rust
- 스타: 109개 (생성일: 2026-10-02)

카메라 RAW 파일을 디코딩하는 Rust 라이브러리로, C·C++·Python·JavaScript(WASM 포함) 바인딩까지 갖춘 0.1.0 버전입니다. raw.pixls.us 코퍼스 2,016개 파일 중 1,980개(98.2%)를 디코딩하는데 그중 1,965개는 고정된 출력 해시로 회귀 테스트까지 통과시켰다고 밝히고 있고, CR3·JPEG XL DNG·GoPro GPR·Sigma X3F·Fuji 압축 RAF 등 다양한 포맷을 지원합니다. x86-64의 SSSE3/SSE4.1, aarch64의 NEON, WASM SIMD128까지 런타임에 선택하는 SIMD 언패킹 커널과 wgpu/WGSL로 CPU·GPU 모두에서 돌리는 단일 패스 RAW→RGB 파이프라인이 핵심 기술이며, LibRaw 대비 7.9~15.4배 빠르다는 벤치마크를 방법론과 함께 공개하면서도 자신이 느린 케이스와 CI 미비 같은 한계도 솔직하게 적어둔 점에서 완성도가 높은 로우레벨 포맷 파서 사례로 공부할 가치가 있습니다.

### LambdaBytes/sping

- <https://github.com/LambdaBytes/sping>
- 언어: Rust
- 스타: 134개 (생성일: 2026-09-30)

"사람을 위한 현대적인 ping"을 표방하는 Rust 네트워크 진단 도구로, 대상이 응답하는지뿐 아니라 게이트웨이·WAN 접근성까지 함께 확인해 장애의 종류를 구분해주는 것이 특징입니다. "서드파티 ping 라이브러리 없이 플랫폼별로 직접 구현한 ICMP"를 내세워, Linux는 `socket2` DGRAM 소켓과 RAW 폴백에 `libc`의 `recvmsg`로 TTL을 읽고, macOS는 DGRAM 소켓에서 IP 헤더를 직접 파싱하고, Windows는 `iphlpapi.dll`의 `IcmpSendEcho`를 FFI로 호출하는 등 OS마다 별도 백엔드를 둔 점이 핵심 아키텍처입니다. 비특권 ICMP를 우선하고 `CAP_NET_RAW`는 RAW 폴백에만 필요하게 설계했으며, 유닛 테스트 330개와 엔드투엔드 테스트 45개를 포함해 375개 테스트, CHANGELOG·JSON 계약·보안 정책·man 페이지까지 문서화해둔 점에서, 크로스플랫폼 저수준 네트워크 도구를 어떻게 안전하게 설계하는지 보여주는 좋은 자료입니다.
