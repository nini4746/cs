오늘 트렌딩은 에이전트를 둘러싼 거버넌스 레이어가 상단을 채우는 하루입니다. Anthropic이 직접 공개한 지식 근로자용 플러그인 모음(knowledge-work-plugins), 에이전트가 과하게 코드를 쓰는 것을 막는 "게으른 시니어처럼 생각하기" 스킬(ponytail), 코딩 에이전트를 보안 감사관으로 바꾸는 스킬(security-audit-skill), 그리고 코드베이스 전체를 질의 가능한 지식 그래프로 바꾸는 도구(graphify)까지, "에이전트에게 무엇을 맡기고 그 결과를 어떻게 검증·구조화할 것인가"라는 질문이 여러 각도에서 반복됩니다. 그 사이에 20년 넘게 웹을 지탱해온 PHP 공식 인터프리터(php-src)가 나란히 올라와 있는 것도 눈에 띄는데, 신규 에이전트 도구들의 화려함과 대비해서 보면 레거시 언어 코어가 여전히 꾸준히 커밋되고 있다는 사실 자체가 공부해볼 만한 지점입니다.

### hieutdo/policyfs

- <https://github.com/hieutdo/policyfs>
- 언어: Go
- 스타: 56
- 생성일: 2026-02-26

여러 개의 저장 경로를 하나의 마운트 지점으로 합쳐주는 Linux FUSE 스토리지 데몬입니다. 경로 패턴에 따라 읽기·쓰기를 어느 저장 위치로 보낼지 정하는 라우팅 규칙을 `/etc/pfs/pfs.yaml`로 설정하고, 디렉터리 목록 조회 시 스핀다운된 HDD를 깨우지 않도록 SQLite 메타데이터 인덱스를 별도 인덱서 서비스로 채워두는 설계가 특징입니다. 인덱싱된 경로에 대한 삭제·이름변경은 즉시 반영하지 않고 이벤트로 기록해두었다가 나중에 적용하는 지연 처리 방식을 쓰며, 단위 테스트(`make test-unit`)와 통합 테스트(`make test-integration`), 커버리지 리포트까지 Docker Compose 기반 개발 환경에서 갖추고 있어 실제 운영을 염두에 둔 완성도가 느껴집니다. FUSE로 "여러 저장소를 하나처럼 보이게" 만드는 가상 파일시스템을 설계할 때 라우팅과 캐싱을 어떻게 분리하는지 참고하기 좋습니다.

### sshoecraft/meshxfs

- <https://github.com/sshoecraft/meshxfs>
- 언어: C
- 스타: 45
- 생성일: 2026-07-20

업스트림 Linux XFS를 포크해서 여러 노드가 같은 블록 디바이스를 동시에 읽고 쓸 수 있게 만든 공유 디스크 클러스터 파일시스템입니다. 네트워크 기반 잠금 관리자(`net/mesh`, TCP 피어투피어)와 공유 LUN 위에 SCSI COMPARE AND WRITE·Persistent Reservation으로 잠금 상태를 저장하는 디스크 기반 잠금 관리자(`disk/caw`) 두 가지를 제공하고, 노드 장애 시 SCSI Persistent Reservation으로 펜싱한 뒤 생존 노드가 저널 슬라이스를 리플레이하는 복구 구조를 갖추고 있습니다. 릴리스마다 클린 빌드·소스 감사·잠금 관리자 단위 테스트에 더해, 캐시 일관성·잠금 경쟁·노드 강제종료·네트워크 분할·경로 장애까지 다루는 설정당 약 31개 항목의 클러스터 테스트 스위트를 통과시켜야 "데이터 손실·크래시·행 없음"이라는 릴리스 기준을 만족한다고 명시하고 있어, 분산 파일시스템의 정합성을 검증하는 테스트 설계를 공부하기에 좋은 사례입니다. 다만 클러스터링·잠금·펜싱 코드는 AI가 작성했고 XFS 자체만 사람이 쓴 기반이라는 점은 참고할 필요가 있습니다.

### cusdeb-com/os

- <https://github.com/cusdeb-com/os>
- 언어: C
- 스타: 67
- 생성일: 2026-04-28

Linux 커널 위에 Win32 유저랜드를 얹어 "Windows 같은" 데스크톱 경험을 만드는 운영체제 프로젝트입니다. CDEX라는 이름의 데스크톱 환경과 번들 앱들을 Win32 API에 맞춰 직접 작성하고, Wine으로 실제 Windows 애플리케이션을 구동하며, Direct3D 3~11 호출을 D7VK·DXVK로 변환하는 지원은 알파 이후 단계로 예정해두는 등 단계적 로드맵이 뚜렷합니다. Debian을 베이스로 삼아 서드파티 구성요소를 모두 Debian 패키지로 포장하고 패키지별 라이선스를 `debian/copyright`로 문서화하는 등, 커널 교체 없이 유저랜드 전체를 다른 OS의 경험으로 바꿔치기하는 접근을 실제로 패키징까지 끌고 간 사례로 볼 만합니다. 테스트나 CI 체계가 README에 드러나 있지 않다는 점은 앞서 소개한 다른 히든잼들과 비교해 아쉬운 부분입니다.
