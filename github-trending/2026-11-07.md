오늘 트렌딩 상위권은 거의 전부 "에이전트에게 무엇을 쥐여줄 것인가"라는 질문으로 채워진 하루입니다. 브라우저를 직접 조작하는 CLI(vercel-labs/agent-browser)부터, Claude Code·Codex 같은 코딩 에이전트에 보안 감사·클라우드 운영·엔지니어링 습관을 통째로 넘기는 스킬 저장소(cloudflare/security-audit-skill, google/skills, mattpocock/skills, anthropics/skills)까지, 다섯 자리 중 네 자리가 "에이전트 스킬" 생태계에 몰려 있습니다. 같은 "스킬"이라는 포맷을 두고 회사(Cloudflare, Google, Anthropic)와 개인 개발자(Matt Pocock)가 동시에 뛰어들고 있다는 점에서, 스킬 파일이 이제 라이브러리나 플러그인만큼 당연한 배포 단위로 자리잡고 있다는 인상을 받습니다.

## vercel-labs/agent-browser

- <https://github.com/vercel-labs/agent-browser>
- 언어: Rust
- 오늘 스타: 180 (총 46,500+)

AI 에이전트가 셸 명령 하나씩으로 브라우저를 조작하게 해주는 CLI입니다. `snapshot` 명령이 페이지를 `@e1` 같은 참조 ID가 붙은 압축된 접근성 트리(accessibility tree) 텍스트로 돌려주면, 에이전트가 그 참조를 보고 동작을 수행한 뒤 다시 읽어들이는 루프로 작동합니다. Rust로 작성된 네이티브 CLI가 세션당 하나씩 뜨는 백그라운드 데몬에 명령을 보내고, 데몬이 Chrome DevTools Protocol로 브라우저(기본은 Chrome for Testing, 또는 Browserbase·Kernel 같은 클라우드 브라우저, iOS 시뮬레이터의 Mobile Safari까지)를 제어하는 구조입니다. 인증 저장소(auth vault)와 도메인 allowlist, 액션 정책으로 안전장치를 두고 MCP 서버 모드까지 제공하는 점에서, "에이전트에게 브라우저 제어권을 어떻게 안전하게 넘길 것인가"를 CLI/데몬 분리 구조로 풀어낸 참고 사례입니다.

## cloudflare/security-audit-skill

- <https://github.com/cloudflare/security-audit-skill>
- 언어: Markdown + Node.js
- 오늘 스타: 2,088 (총 65,000+)

코딩 에이전트를 보안 감사관으로 바꿔주는 Cloudflare의 스킬로, 정찰→커버리지 기반 탐색→후보 검증→구조화된 출력→독립 재검증→리포팅의 6단계로 작업을 쪼갭니다. 각 발견 사항은 confirmed/needs validation/rejected 세 등급 중 하나를 받고, 별도 에이전트가 후보를 반증하려 시도하는 적대적 검증(adversarial validation) 단계를 구조적으로 끼워넣은 점이 특징입니다. 커버리지 레저와 의존성 없는 Node.js 검증기로 `findings.json`을 JSON 스키마에 맞춰 검사하고, 네트워크가 끊긴 OS 샌드박스가 없으면 리드를 실행하지 않고 미검증 상태로 남겨두는 식으로 "검증되지 않은 결과를 함부로 확정하지 않는" 설계 원칙이 눈에 띕니다. 에이전트의 자기 보고를 어떻게 구조적으로 못 믿게 만들 것인가에 대한 실전적인 답을 보여주는 저장소입니다.

- 언어: Markdown
- 오늘 스타: 449 (총 23,100+)

Google Cloud 제품들(Gemini, Vertex 계열 에이전트 플랫폼, GKE, BigQuery, Spanner, IAM, Cloud Run 등)을 다루는 Agent Skills 모음입니다. `npx skills add google/skills`로 설치하고 업데이트할 수 있으며, Skills 포맷에 Claude Code·Codex·Antigravity CLI용 MCP 서버를 결합한 "제품 플러그인"을 함께 묶어두는 구조가 특징입니다. 디렉터리별 Markdown 스킬 파일, 플러그인 매니페스트(`.claude-plugin`), 루트 `index.json`, lychee로 링크를 검사하는 GitHub Actions까지 갖춘 걸 보면 대형 회사가 수백 개의 제품별 지식을 스킬 형태로 유지보수하는 운영 패턴을 엿볼 수 있습니다. 클라우드 제품 하나하나의 베스트 프랙티스를 "스킬"이라는 단위로 쪽수를 쪼개 배포하는 방식 자체가 참고할 만합니다.

### Daniele-Cangi/xcp-xbox

- <https://github.com/Daniele-Cangi/xcp-xbox>
- 언어: C++ · 스타: 68 · 생성일: 2026-09-25

Xbox Series X의 Developer Mode에서 워크로드를 실행하기 위한 개발/실행 시스템입니다. Windows의 XCP Studio(WinUI 앱)에서 프로젝트를 만들고 검증하면, Xbox 쪽의 XCP Worker(네이티브 UWP 런타임)가 CPU는 별도 패키징된 "CPU Capsule"로, GPU는 Direct3D compute·사전 컴파일된 HLSL 경로로 실행하며, 결과를 구조화된 데이터와 "증거(evidence)"로 돌려받는 구조입니다. 특히 XVM이라는 자체 v2 ISA 기반 가상머신(어셈블러·검증기·결정론적 CPU 레퍼런스 인터프리터·연료(fuel) 분석·타입 메모리·스냅샷 포함)을 Xbox 하드웨어 없이도 PC에서 돌릴 수 있게 만들어 둔 점이 특징이며, "증거보다 강한 주장은 할 수 없다"는 원칙 아래 하드웨어에서 재검증되지 않은 패키지에는 `NOT_TESTED_ON_XBOX` 라벨을 붙여둡니다. CI와 CodeQL 배지, `tests/` 디렉터리, 빌드 후 재검증 단계까지 갖추고 있고 README에서 "임의의 Godot 프로젝트를 자동 변환하지 않는다", "탈옥 도구가 아니다" 같은 한계를 스스로 명시하는 점에서 신뢰할 만한 공개 방식을 보여줍니다.

### kanywst/wtfi2

- <https://github.com/kanywst/wtfi2>
- 언어: Rust · 스타: 106 · 생성일: 2026-07-17

보관된 프로젝트 `wtfi`를 처음부터 다시 쓴 네트워크 진단 CLI/TUI로, "나 → Wi-Fi → 게이트웨이 → 업링크 → 인터넷 → DNS → 포털" 경로를 그려 보여주면서 어느 홉이 먼저 끊겼는지와 신뢰도가 붙은 근본 원인 하나를 알려줍니다. OS별 차이를 `Platform` 트레이트 뒤로 숨기고 macOS(CoreWLAN, `route`, `scutil`)와 Linux(`ip`, `iw`, `resolv.conf`) 각각의 모듈로 나눈 구조, 지원하지 않는 플랫폼에서는 거짓 결과 대신 즉시 실패하고 종료 코드 3을 내는 설계, `--json` 출력과 0~4로 코드화된 종료 코드로 스크립트에서 쓸 수 있게 만든 점이 돋보입니다. `tests/cli.rs`에서 실제 바이너리를 실행해 종료 코드와 상태 일치를 검사하는 테스트와 GitHub Actions CI, 그리고 `--bundle`로 식별 정보를 가린 마크다운 리포트를 만들고 `--mcp`로 에이전트에 데이터를 노출하는 기능까지 갖춘, README만으로도 설계 의도가 명확하게 읽히는 저장소입니다.
