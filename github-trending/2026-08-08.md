오늘 트렌딩은 "에이전트 스킬" 생태계가 한 단계 더 넓어진 하루입니다. 그동안 개인·팀 단위로 스킬 모음을 공개해온 addyosmani/agent-skills와 mattpocock/skills 옆에, 구글이 직접 내놓은 google/skills가 나란히 상위권에 오르면서 스킬 파일이 개인 프로젝트를 넘어 빅테크가 공식적으로 배포하는 형태로 자리잡는 흐름이 뚜렷해졌습니다. 여기에 세션 경계를 넘어 상태를 유지하는 장기 자율 에이전트 PrimeIntellect-ai/prime-agent가 다시 최상위권에 오른 것도 눈에 띄고, 코딩과는 결이 다른 TapXWorld/ChinaTextbook이 교육 자료 접근성이라는 주제로 함께 트렌딩에 오른 것이 오늘의 특이점입니다.

## PrimeIntellect-ai/prime-agent

- <https://github.com/PrimeIntellect-ai/prime-agent>
- 언어: TypeScript
- 오늘 스타: 2,483 (총 약 8,000)

컨텍스트를 변수로, 도구를 함수 호출로 다루는 "재귀적 언어 모델(RLM)"과 세션을 넘어 상태를 유지하는 "Continual Harness"를 두 축으로 하는 장기 자율 에이전트로, 이번 주 내내 트렌딩을 오가다 오늘 다시 상위권 최상단에 올랐습니다. `rlm(...)` 호출로 서브에이전트를 병렬·백그라운드로 띄우고, 터미널 연결이 끊겨도 유지되는 데몬 기반 세션으로 재접속할 수 있는 구조는, 채팅창이 닫히면 진행 상황을 잃어버리는 에이전트의 한계를 세션 밖에 영속 상태를 두는 방식으로 풀어보려는 시도입니다. 하루 만에 2천 개가 넘는 스타가 다시 붙은 것을 보면, "장기 실행 가능한 에이전트"에 대한 관심이 일시적 화제가 아니라 꾸준히 이어지고 있다는 신호로 읽힙니다.

### aicheye/crustty

- <https://github.com/aicheye/crustty>
- 언어: Rust
- 스타: 54 (2026-02-08 생성)

Rust로 만든 교육용 C 인터프리터로, 시간을 되돌려가며 디버깅할 수 있는 TUI 디버거가 핵심입니다. 손으로 짠 재귀 하강 파서(이항 연산자는 precedence climbing)로 `int`/`char`/구조체/포인터/배열과 `if`·`while`·`for`·`switch` 등 C의 실용적인 부분집합을 지원하고, 스택은 `0x0000_0004`부터, 힙은 `0x7fff_0000`부터 시작하는 두 개의 겹치지 않는 주소 공간으로 포인터 혼동을 막습니다. 매 실행 스텝마다 스택·힙·터미널 출력·현재 소스 위치 전체를 스냅샷으로 저장해두기 때문에 ratatui 기반 5분할 TUI에서 실행을 앞뒤로 오가며 콜스택과 메모리 할당을 그대로 들여다볼 수 있고, `cargo test`로 단위·통합 테스트를 돌리는 구조까지 갖춰서 "프로덕션용이 아니라 교육용"이라고 스스로 명시한 점까지 포함해 인터프리터와 디버거를 함께 밑바닥부터 구현해보는 참고 자료로 좋습니다.

### confh/Tiny

- <https://github.com/confh/Tiny>
- 언어: Go
- 스타: 57 (2026-05-07 생성)

소스를 스택 기반 바이트코드(`.tbc`)로 컴파일해 슬롯 기반 로컬 저장 방식의 VM에서 실행하는 동시성 지향 언어로, 일반 로직은 인터프리터가, 핫 루프는 JIT이 네이티브 WebAssembly로 변환해 처리하는 다단계 실행 모델을 갖추고 있습니다. 동시성은 이벤트 루프가 아니라 OS 스레드를 그대로 사용하는데, `spawn` 키워드로 격리된 VM 상태 공간에서 새 실행 루틴을 띄우고 `lock` 블록을 벗어나면 자동으로 잠금이 풀리는 방식으로 데드락을 막습니다. `http`·`websocket`·`sqlite`·`desktop`·`ui` 등 20개가 넘는 표준 라이브러리 모듈과, 구문 오류 중에도 진단을 유지하는 "시맨틱 복구" 기능을 갖춘 자체 LSP까지 갖추고 있어, 바이트코드 VM과 JIT을 함께 설계할 때 어디까지 도구 체인에 투자하는지 보여주는 사례입니다.

### multikernel/daxfs

- <https://github.com/multikernel/daxfs>
- 언어: C
- 스타: 93 (2026-01-24 생성)

여러 커널 인스턴스나 CXL로 연결된 여러 호스트가 DAX 메모리를 공유 파일시스템처럼 쓸 수 있게 만드는 프로젝트로, 락 대신 CAS(`cmpxchg`) 기반의 락-프리 조율을 씁니다. 오버레이는 16바이트 버킷의 오픈 어드레싱 해시 테이블로 구성되어 버킷의 `state_key`를 FREE→USED로 CAS 전환하는 방식으로 동시 쓰기를 처리하고, inode와 페이지 오프셋을 63비트로 인코딩해 파일당 최대 약 100만 페이지를 지원합니다. 공유 페이지 캐시는 FREE→PENDING→VALID 3단계 상태 머신으로 동작해 호스트 커널이 슬롯을 채우는 동안 다른 커널은 VALID가 될 때까지 busy-poll하는 구조이며, 같은 하드웨어 캐시 일관성 도메인 안에서는 별도 프로토콜 없이 하드웨어 자체 일관성만으로 가시성을 보장하지만 호스트를 넘나드는 CXL 공유는 아직 "미래 과제"로 남겨뒀다고 명시하고 있습니다. 파일명 255자 제한, 생성 시 고정되는 해시 테이블 크기, mknod 미지원 같은 한계까지 문서에 솔직하게 적어둔 점에서, CXL 시대의 공유 메모리 파일시스템이 락-프리 동시성을 어떻게 설계하는지 깊이 있게 들여다볼 수 있는 자료입니다.
