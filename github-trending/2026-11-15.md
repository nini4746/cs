오늘 트렌딩은 "에이전트가 다루는 대상이 코드를 넘어 문서·브라우저·UI까지 넓어지고 있다"는 흐름이 뚜렷한 하루입니다. 오피스 문서를 에이전트가 직접 읽고 쓰게 만드는 SDK(univer), 에이전트와 프런트엔드 사이의 통신을 표준화하는 프로토콜(ag-ui), 디자인 툴을 에이전트 스킬로 감싸는 라이브러리(stitch-skills), 에이전트 산출물을 사람이 검토하도록 돕는 로컬 리뷰 도구(plannotator), 그리고 에이전트가 실제 브라우저를 제어하게 해주는 MCP 서버(chrome-devtools-mcp)까지, 다섯 레포 모두 "에이전트가 무엇을 직접 조작할 수 있는가"라는 질문을 서로 다른 층위에서 다루고 있습니다.

## dream-num/univer

- <https://github.com/dream-num/univer>
- 언어: TypeScript
- 오늘 스타: 1,041 (총 25,303)

스프레드시트와 문서 편집을 애플리케이션에 통째로 끌어다 쓸 수 있게 만든 오피스 SDK입니다. 기능별 플러그인(예: `sheets-filter`와 `sheets-filter-ui`)이 의존성 주입으로 연결되고, 커맨드가 편집을 조율하고 뮤테이션이 직렬화 가능한 스냅숏(`IWorkbookData` 등)을 바꾸는 구조를 공유 수식 엔진·렌더링 엔진과 함께 쓰는 점이 핵심입니다. 최근에는 이 직렬화된 "Unit" 스냅숏을 사람뿐 아니라 AI 에이전트도 그대로 들여다보고 "Worktree" 초안으로 수정 제안을 올리게 하는 AI SDK와 코딩 에이전트용 스킬을 추가했는데, 문서 데이터 모델을 사람의 UI와 에이전트의 API가 동시에 소비하도록 설계하는 방법을 참고하기 좋은 사례입니다.

## ag-ui-protocol/ag-ui

- <https://github.com/ag-ui-protocol/ag-ui>
- 언어: TypeScript
- 오늘 스타: 393 (총 17,619)

에이전트 백엔드와 사용자 화면을 잇는 오픈 프로토콜로, MCP(에이전트-도구)와 A2A(에이전트-에이전트) 사이에서 "에이전트-사용자" 계층을 표준화하려는 시도입니다. 약 16종의 표준 이벤트 타입으로 스트리밍 채팅, 양방향 상태 동기화, 생성형 UI, 프런트엔드 도구 호출, 휴먼인더루프 승인 같은 패턴을 SSE·웹소켓 등 어떤 전송 계층 위에서도 느슨하게 매칭할 수 있게 정의합니다. Kotlin·Go·Rust·.NET 등 다양한 언어 SDK와 LangChain·CrewAI·Pydantic AI 같은 프레임워크 연동을 갖춘 pnpm/Nx 모노레포 구조를 보면, 에이전트와 UI 사이의 통신을 특정 프레임워크에 묶지 않고 설계하는 법을 공부하기 좋습니다.

- <https://github.com/backnotprop/plannotator>

- 오늘 스타: 860 (총 11,634)

Claude Code, Codex, Gemini CLI 등 여러 코딩 에이전트의 plan mode 제안과 PR/MR diff를 브라우저 UI에서 주석 달아 되돌려주는 로컬 리뷰 도구로, 어제도 트렌딩에 올랐던 데 이어 오늘 스타가 가장 크게 늘었습니다. 각 에이전트의 훅(예: Claude Code의 `PermissionRequest`)으로 plan 제안을 가로채 Bun 기반 로컬 서버가 브라우저 UI를 띄우고, 에이전트가 질문·파일·리뷰 요청을 올리는 "Inbox" 창까지 더해졌습니다. 텔레메트리 없이 로컬에만 머무르면서 Git·GitButler·Jujutsu·Perforce diff까지 폭넓게 지원하는 구조는, "에이전트와의 대화창"이 아니라 "에이전트 산출물을 검토하는 전용 화면"을 어떻게 별도로 설계하는지 보여주는 사례입니다.

가비지 컬렉터 없이 포터블 C로 컴파일되는 작은 언어로, 메모리 소유권·이펙트·자원 작업 순서를 전부 컴파일 타임에 검사합니다. 값은 리전에 살고 아레나/힙 핸들러가 관리하며, capability라는 타입스테이트 상태 기계로 "이미 해제된 자원을 또 해제하지 않는다", "자원을 닫지 않고 끝내지 않는다" 같은 규칙을 강제합니다. 함수가 필요한 이펙트를 타입에 명시하고 `main`이 그 이펙트를 전부 핸들러로 열어야 외부 세계(파일·환경변수·시간·네트워크)에 닿을 수 있게 만든 설계가 핵심이며, 컴파일러 `s2c` 자체를 srs로 작성해 자기 자신을 바이트 단위로 동일하게 재생성하는 self-hosting까지 갖췄습니다. README가 기능별로 `prog/`(성공 사례)와 `neg/`(실패해야 하는 사례) 테스트를 구체적으로 연결해두고, 부트스트랩 검사와 전체 테스트 스위트를 돌리는 게이트 스크립트, 타입 시스템·리전·타입스테이트·이펙트 관련 참고문헌까지 정리해둔 점에서 완성도가 높습니다. 리전 기반 메모리 관리와 이펙트 시스템을 GC 없이 어떻게 같이 설계하는지 공부하기 좋은 레포입니다.

### tizoc/shen-jit

- <https://github.com/tizoc/shen-jit>
- 언어: C / Shen
- 스타: 7, 생성일: 2026-11-05

Lisp 계열 언어 Shen을 호스트 언어 없이 기계어로 직접 컴파일하는 네이티브 구현체입니다. 함수를 레지스터 기반 바이트코드로 낮춘 뒤 SLJIT 위에 만든 베이스라인 JIT로 컴파일하는 구조이며, 이 낮추기(lowering) 단계 자체를 Shen으로 작성해 자기 자신을 컴파일하게 만든 점이 눈에 띕니다. 런타임은 C 약 1만 1,700줄, 로워러와 포팅 코드는 Shen 약 2,000줄로 규모를 README에 구체적으로 밝히고 있고, Shen 커널의 테스트 스위트와 확장 테스트, contract 예제까지 통과했다고 보고하며 macOS·Linux·Windows를 지원합니다. 벤더링한 의존성(SLJIT, xxHash)마다 `UPSTREAM.md`로 가져온 리비전을 명시하는 등 사소한 부분까지 문서화가 꼼꼼해, 기존 언어를 바이트코드와 JIT으로 네이티브화하는 과정을 작은 규모에서 들여다보기 좋은 자료입니다.
