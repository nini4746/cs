## cloudflare/computer

- <https://github.com/cloudflare/computer>
- 언어: TypeScript
- 오늘 스타: 2,690 (총 4,497)

에이전트에게 영속적인 파일시스템과 실행 환경을 붙여주는 모노레포로, Durable Object가 SQLite로 상태를 관장하고 `workspace.runtime`이라는 단일 진입점 뒤에 컨테이너·아이솔레이트 셸·아이솔레이트 JavaScript 세 가지 실행 백엔드를 감춥니다. 컨테이너 백엔드는 SQLite 상태를 FUSE 마운트로 샌드박스에 투영해 리눅스 바이너리를 그대로 돌리고, 아이솔레이트 셸은 Workers RPC로 워크스페이스에 직접 접근해 동기화 왕복 없이 상태를 공유합니다. `@cloudflare/dofs`(가상 파일시스템), `@cloudflare/computer-rpc`(와이어 타입), `@cloudflare/computerd`(데몬) 등 다섯 개 패키지로 나뉜 구조는, 에이전트 실행 환경을 추상화하며 백엔드 전환 비용을 낮추는 설계를 참고하기 좋습니다.

### Kludex/zttp

- <https://github.com/Kludex/zttp>
- 언어: Zig (Python 바인딩)
- 스타: 40 (2026-06-07 생성)

HTTP/1.1, HTTP/2, HTTP/3를 모두 지원하는 sans-IO HTTP 파서로, 손으로 작성한 Zig 엔진 위에 Python 바인딩을 얹은 구조입니다. I/O를 직접 하지 않고 바이트를 넣으면 `Request`/`Data`/`EndOfMessage` 같은 이벤트를 돌려주는 방식이라, HTTP/1.1의 단순 요청이든 HTTP/2의 스트림 멀티플렉싱이든 HTTP/3의 UDP 기반 통신이든 동일한 이벤트 API로 다룰 수 있습니다. 벤치마크 스위트 14개 워크로드 중 13개에서 httptools를 능가하고 순수 파이썬 대비 약 15배 빠르다고 밝히면서도, 기본으로 bare LF를 거부하는 엄격한 CRLF 처리와 두 차례의 적대적 보안 감사, THREAT_MODEL.md 문서, Zig의 안전 검사 빌드로 메모리 소진 공격까지 방어하는 등 성능과 보안을 함께 신경 쓴 점이 눈에 띕니다. 프로토콜 파서를 I/O와 분리해서 설계하는 sans-IO 패턴과, 여러 HTTP 버전을 하나의 이벤트 모델로 통합하는 방법을 공부하기 좋은 자료입니다.

- 스타: 38 (2026-07-12 생성)

CGO 없이 순수 Go로 구현된 WebAssembly 런타임으로, Rust·C++·Zig·TinyGo로 컴파일된 Wasm 모듈을 외부 툴체인 없이 임베드해 실행할 수 있습니다. amd64/arm64에서는 네이티브 머신 코드로 컴파일하는 최적화 엔진을, 그 외 아키텍처에서는 순수 Go 인터프리터를 쓰는 이중 엔진 구조이고, Go의 제네릭 타입에서 Wasm 시그니처를 컴파일 타임에 도출해 리플렉션 오버헤드를 없앤 호스트 함수 바인딩도 특징입니다. Core Wasm 1.0/2.0에 더해 WASI 0.1~0.3 async ABI와 Canonical ABI(값 타입별 lift/lower)까지 지원하며 31개 공식 Component Model async conformance suite를 통과했고, wazero 대비 호스트 호출 최대 15배, 메모리 확장 22배 빠르다는 벤치마크를 OPTIMIZATIONS.md에 재현 가능한 방법론과 함께 공개하고 있어, Wasm 런타임을 밑바닥부터 구현할 때 표준 준수와 성능을 어떻게 동시에 검증하는지 보여주는 사례입니다.

### manticorephp/compiler

- <https://github.com/manticorephp/compiler>
- 언어: PHP
- 스타: 31 (2026-06-12 생성)

PHP 8.5+ 코드를 ARM64/x86_64용 네이티브 바이너리로 컴파일하는 자체 호스팅(self-hosted) AOT 컴파일러로, "컴파일러 자체가 PHP로 작성되어 있고 스스로를 바이트 단위로 동일한 고정점까지 컴파일한다"는 점이 핵심입니다. 렉서·재귀 하강 파서로 AST를 만든 뒤 "평평하고 타입이 있는 SSA에 가까운 IR"인 MIR로 낮추고, 상수 폴딩·타입 추론·제네릭 단형화·데드코드 제거를 포함한 약 15개의 순차 최적화 패스를 거쳐 LLVM IR을 생성한 뒤 clang으로 오브젝트 코드를 만들어 정적 링크하는 파이프라인을 갖추고 있습니다. AOT 테스트 하네스, PHP의 Zend 인터프리터와 결과를 대조하는 차분 테스트, "2세대 IR == 3세대 IR"을 확인하는 셀프 호스팅 고정점 검증까지 세 가지 테스트 체계를 두고 있고, 워크로드에 따라 인터프리터 대비 1.5배에서 44배, 콜드 스타트를 62ms에서 2.6ms로 줄였다는 성능 검증까지 갖춰, 자체 언어로 자기 자신을 컴파일하는 컴파일러를 설계할 때 어떤 정합성 검증 체계를 쌓아야 하는지 보여주는 사례입니다.
