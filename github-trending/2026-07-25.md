오늘 트렌딩은 "에이전트가 코드를 얼마나 잘, 얼마나 안전하게 대신 다뤄줄 수 있는가"라는 주제가 여러 각도에서 반복됩니다. Block의 협업 인프라(buzz)는 사람과 에이전트가 같은 이벤트 로그를 공유하도록 이어가고, 알리바바가 내놓은 코드 리뷰 CLI(open-code-review)는 사내에서 수만 명 규모로 검증한 리뷰 자동화를 오픈소스로 풀었으며, ego-lite는 사람과 에이전트가 같은 브라우저에서 충돌 없이 나란히 작업하는 실행 환경을 제안합니다. 여기에 방법론 자체를 패키징한 에이전트 개발 워크플로(superpowers)와 스킬 큐레이션 저장소(awesome-claude-skills)까지 겹치면서, 에이전트 활용이 개별 도구를 넘어 "협업 프로토콜"과 "개발 방법론" 수준으로 넘어가는 흐름이 뚜렷합니다.

## block/buzz

- <https://github.com/block/buzz>
- 언어: Rust
- 오늘 스타: 2,506 (총 11,199)

Block(舊 Square)이 만든 셀프호스팅 워크스페이스로, Nostr relay를 기반 삼아 사람과 AI 에이전트가 같은 이벤트 로그 위에서 프로젝트·코드리뷰·워크플로·인시던트 대응을 함께 처리하도록 설계되었습니다. 어제에 이어 오늘도 트렌딩 1위를 지키며 다시 2,500개 넘는 스타가 붙었는데, `buzz-relay`(Axum WebSocket/REST), `buzz-db`(PostgreSQL), `buzz-pubsub`(Redis), `buzz-media`(S3/MinIO) 등으로 나뉜 Rust crate 구조와 에이전트마다 별도 암호학적 identity·감사 로그를 부여하는 설계는, 에이전트를 "봇"이 아니라 자체 신원을 가진 참여자로 다루는 협업 인프라를 공부하기 좋은 사례로 계속 남아 있습니다.

## alibaba/open-code-review

- <https://github.com/alibaba/open-code-review>
- 언어: Go
- 오늘 스타: 1,066 (총 12,689)

알리바바 내부에서 수만 명 개발자를 대상으로 검증한 코드 리뷰 어시스턴트를 오픈소스로 공개한 CLI 도구입니다. Git diff를 분석해 LLM에게 넘기되, 파일 선택·번들링·룰 매칭 같은 결정적(deterministic) 작업은 엔지니어링 로직이 처리하고 동적 판단과 컨텍스트 탐색만 에이전트에 맡기는 "Deterministic Engineering × Agent Hybrid" 구조가 핵심입니다. 같은 모델을 쓰는 범용 에이전트 대비 토큰을 약 9분의 1만 쓰면서도 정밀도와 F1 점수가 더 높다고 밝히고 있어, LLM 기반 도구를 만들 때 어디까지를 결정적 로직으로 남기고 어디부터 에이전트에게 위임할지 가르는 설계를 구체적으로 볼 수 있는 프로젝트입니다.

## obra/superpowers

- <https://github.com/obra/superpowers>
- 언어: Shell
- 오늘 스타: 600 (총 260,880)

코딩 에이전트를 위한 개발 방법론을 스킬 형태로 패키징한 프로젝트로, 브레인스토밍(스펙을 코드 짜기 전에 질문으로 다듬기) → Git 브랜치 격리 → 계획(2~5분 단위 작업으로 쪼개기) → 서브에이전트 개발(2단계 리뷰) → red-green-refactor TDD → 리뷰 → 병합·정리까지 이어지는 자동화된 워크플로를 제공합니다. Claude, Cursor, GitHub Copilot, Gemini 등 11개 이상의 코딩 에이전트를 지원하고 서브에이전트가 사람 개입 없이 몇 시간씩 자율적으로 작업하도록 설계된 점이 특징입니다. YAGNI·DRY 같은 원칙을 명시적으로 강제한다는 점에서, "에이전트에게 방법론까지 스킬로 넘긴다"는 접근을 구체적으로 살펴보기 좋습니다.

### timur-developer/gcscope

- 언어: Go, 스타: 36, 생성일: 2026-05-23

Go 런타임의 GC 동작을 실시간 TUI로 시각화하는 관찰 도구입니다. 실행 중인 바이너리에 `GODEBUG` 플래그를 주입해 `gctrace` 출력을 파싱하는 run 모드와, `runtime/metrics`를 노출하는 HTTP 엔드포인트를 폴링하는 attach 모드 두 가지 데이터 수집 경로를 갖추고 있고, STW 정지 시간·힙 live/goal·페이서(pacer) 신호까지 다룹니다. `make test`/`make lint`/`make ci`가 포함된 빌드 체계, JSON 스냅샷 기반 회귀 비교, alloc/churn/idle/spike 네 가지 내장 합성 워크로드까지 갖춘 걸 보면 단순 토이 프로젝트가 아니라 실제 부하 테스트에 쓰라고 만든 도구입니다. GC를 블랙박스로 두지 않고 관찰 가능하게 만드는 계측 설계를 배우기 좋습니다.

### samyeyo/clx

- <https://github.com/samyeyo/clx>
- 언어: C++, 스타: 135, 생성일: 2026-06-14

Lua 5.5 호환 스크립트를 인터프리터 없이 네이티브 실행 파일로 바로 컴파일하는 AOT(ahead-of-time) 컴파일러입니다. C++20으로 작성됐고 Clang/GCC/MSVC 툴체인을 그대로 활용해 기계어를 생성하며, "8바이트 payload + 별도 타입 태그"로 이루어진 16바이트 태그드 값 표현과 6바이트 이하 문자열의 제로 할당 인라인 최적화 같은 저수준 설계가 문서화되어 있습니다. fib.lua 벤치마크에서 표준 Lua 5.5 대비 62.20배 빠르다는 구체적 수치를 제시하고, tests/ 아래 .lua 파일을 실제로 컴파일·실행해 검증하는 테스트 체계와 "Runtime Internals", "Architecture Overview" 같은 상세 문서까지 갖췄습니다. 동적 언어를 AOT로 컴파일할 때 값 표현과 메모리 레이아웃을 어떻게 설계하는지 실제 구현으로 보기 좋은 프로젝트입니다.

### rustic-compiler/rustc_codegen_c

- <https://github.com/rustic-compiler/rustc_codegen_c>
- 언어: Rust, 스타: 92, 생성일: 2026-04-07

Rust 컴파일러의 LLVM 백엔드 대신 MIR(Mid-level IR)을 C 소스 코드로 변환하는 대체 코드젠 백엔드입니다. 생성된 C 코드를 gcc나 clang 같은 일반 C 컴파일러로 다시 컴파일해 실행 파일을 만드는 방식이라, LLVM이 없어도 C 툴체인만 있으면 Rust를 컴파일할 수 있게 해줍니다. 이 백엔드로 빌드한 Rust 컴파일러가 공식 rustc UI 테스트 스위트의 99.2%를 통과한다고 밝히고 있어 의미 보존이 상당히 탄탄하다는 것을 알 수 있고, `ring`처럼 CPU 특화 명령어에 의존하는 일부 크레이트가 실패할 수 있다는 한계까지 투명하게 문서화되어 있습니다. 대형 컴파일러의 백엔드를 통째로 갈아끼우는 실험을 어떻게 검증 가능한 수준까지 끌고 가는지 참고할 만합니다.

### multikernel/daxfs

- <https://github.com/multikernel/daxfs>
- 언어: C, 스타: 93, 생성일: 2026-01-24

CXL로 연결된 여러 커널·호스트가 잠금 없이 바이트 단위 메모리를 공유 스토리지처럼 쓸 수 있게 하는 파일시스템입니다. 블록 디바이스가 아니라 DAX(direct access)로 메모리를 직접 load/store하고, 저널링 대신 DAX 메모리 위의 CAS 기반 해시 테이블로 여러 호스트의 동시 쓰기를 잠금 없이 조율하는 것이 핵심 아이디어입니다. 온디스크 포맷(버전 7)에 슈퍼블록·베이스 이미지·오버레이 버킷 배열·페이지 캐시 구조를 상세히 명세하고, 순환 참조 공격을 막기 위해 일부러 플랫 디렉터리 구조를 택했다는 보안 설계 근거까지 문서화했으며, `mkdaxfs`·`daxfs-inspect` 같은 실전 도구와 FamFS·tmpfs·overlayfs와의 아키텍처 트레이드오프 비교표도 갖췄습니다. CXL 시대의 공유 메모리 파일시스템을 락-프리로 설계할 때 무엇을 고민해야 하는지 구체적으로 보여주는 시스템 프로그래밍 사례입니다.
