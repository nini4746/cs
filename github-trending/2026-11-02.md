오늘 트렌딩은 "에이전트에게 어떤 능력을 더 얹어줄 것인가"가 거의 모든 상위권을 관통하는 하루입니다. 여러 코딩 에이전트를 하나의 앱으로 묶어 조작하는 t3code가 가장 큰 폭으로 스타를 모았고, 그 바로 뒤를 OS 접근성 트리를 읽어 데스크톱 앱을 직접 조작하는 agent-desktop, 세션을 넘나드는 기억을 주는 claude-mem, 단일 세션을 게임 스튜디오로 바꿔주는 멀티 에이전트 템플릿(Claude-Code-Game-Studios)이 따라붙습니다. 그 사이에 자리한 Python 스크래핑 프레임워크 Scrapling은 방향이 조금 다르지만, MCP 서버와 에이전트 스킬을 함께 제공한다는 점에서 역시 "에이전트가 쓰기 좋은 도구"라는 흐름 안에 있습니다. 조작(control), 신체(computer use), 기억(memory), 역할(role template)까지 에이전트의 구성 요소가 한 줄로 늘어선 모양새입니다.

- <https://github.com/pingdotgg/t3code>
- 언어: TypeScript
- 오늘 스타: 3,216 (총 40,602)

Claude Code, Codex, Cursor CLI, Grok Build 등 여러 코딩 에이전트를 각자의 CLI 대신 하나의 모바일·웹·데스크톱 앱에서 조작할 수 있게 해주는 "에이전트 하네스 컨트롤 서페이스"입니다. pnpm 워크스페이스로 묶인 모노레포에 로컬 서버(`t3` 명령)가 각 에이전트를 구동하고 MCP로 외부 연결까지 지원하는 구조인데, winget·Homebrew·AUR·Nix까지 아우르는 배포 범위를 보면 "어떤 에이전트를 쓰든 조작 화면은 하나로 통일한다"는 목표가 꽤 진지합니다. 여러 벤더의 CLI 에이전트를 단일 프로토콜로 추상화하려는 시도라는 점에서, 에이전트 오케스트레이션 UI를 설계할 때 참고할 사례입니다.

## vercel-labs/agent-desktop

- <https://github.com/vercel-labs/agent-desktop>
- 언어: Rust
- 오늘 스타: 2,243 (총 8,516)

스크린샷을 보고 클릭 좌표를 추측하는 기존 컴퓨터 유즈 방식과 달리, OS의 접근성(accessibility) API를 통해 앱의 실제 UI 구조를 JSON 스냅샷으로 읽어 각 요소에 안정적인 `ref`를 부여하고, 그 ref에 행동한 뒤 다시 스냅샷을 찍어 검증·재시도하는 구조의 Rust 기반 CLI입니다. macOS·Windows·Linux(AT-SPI)별 어댑터 크레이트로 플랫폼을 분리하고, C FFI 라이브러리까지 제공해 다른 언어에서도 임베드할 수 있게 했습니다. "화면을 보고 추측"하는 대신 "구조를 읽고 검증"하는 방식으로 컴퓨터 유즈의 신뢰성을 높이려는 설계를 구체적으로 볼 수 있는 프로젝트입니다.

## thedotmack/claude-mem

- 언어: TypeScript
- 오늘 스타: 1,799 (총 110,389)

세션이 끝나면 기억을 잃는 코딩 에이전트에게 지속적인 컨텍스트를 주는 메모리 시스템으로, SessionStart부터 PostToolUse까지 여러 생명주기 훅에서 작업 내용을 기록·압축한 뒤 다음 세션에 관련 맥락만 다시 주입합니다.
