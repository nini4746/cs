오늘 트렌딩은 코딩 에이전트를 "어떻게 더 잘 쓰게 만들 것인가"라는 질문이 거의 모든 상위권 레포를 관통하는 하루입니다. 학습 과정 전체를 에이전트에게 맡기는 워크스페이스(DeepTutor), 에이전트가 따라야 할 개발 방법론을 스킬로 정식화한 프레임워크(superpowers), 에이전트가 만든 UI의 "AI 티"를 잡아내는 디자인 감사 도구(impeccable), 에이전트를 위한 전용 IDE(JetBrains ThinkRail), 그리고 여러 에이전트를 팀처럼 묶어 운영하는 채팅 앱(OpenMausBot)까지, 코드 생성 자체보다 에이전트를 둘러싼 방법론·도구·환경 쪽으로 관심이 옮겨가고 있다는 인상을 줍니다.

## HKUDS/DeepTutor

- <https://github.com/HKUDS/DeepTutor>
- 언어: Python
- 오늘 스타: 1,926

"평생 개인화 튜터링"을 표방하는 에이전트 네이티브 학습 워크스페이스입니다. 채팅, 퀴즈, 리서치, 시각화, 숙련도 연습 등 여러 학습 모드가 하나의 런타임과 세션 컨텍스트를 공유하고, 지식 베이스마다 LlamaIndex·GraphRAG·LightRAG 등 여러 RAG 엔진을 골라 쓸 수 있습니다. 특히 메모리를 벡터 스토어에 숨기지 않고 L1(트레이스)·L2(사실)·L3(종합)의 3계층 파일로 저장해 사람이 직접 들여다보고 고칠 수 있게 한 점, `deeptutor kb eval` 명령으로 Recall@k·nDCG@k·MRR 같은 지표를 직접 재보고 검색 엔진을 비교할 수 있게 한 점이 눈에 띕니다. RAG 품질을 감으로 판단하지 않고 측정하는 구조를 공부하기 좋은 레포입니다.

## obra/superpowers

- <https://github.com/obra/superpowers>
- 언어: Shell
- 오늘 스타: 1,037

코딩 에이전트를 위한 "완전한 소프트웨어 개발 방법론"을 스킬 묶음으로 패키징한 프로젝트입니다. brainstorming(요구사항 도출) → writing-plans(파일 경로·검증 단계까지 포함한 계획 수립) → executing-plans/subagent-driven-development(실행과 2단계 리뷰) → test-driven-development(RED-GREEN-REFACTOR 강제) → finishing-a-development-branch(머지 판단)로 이어지는 단계가 전부 자동 트리거되는 "의무적 워크플로"로 설계되어 있습니다. Claude Code, Codex, Cursor, Gemini CLI 등 여러 에이전트 하네스에 플러그인 형태로 설치할 수 있어, TDD·YAGNI 같은 원칙을 마크다운 스킬 파일로 어떻게 강제할 수 있는지 구체적으로 볼 수 있습니다.

## pbakaus/impeccable

- <https://github.com/pbakaus/impeccable>
- 언어: Rust
- 오늘 스타: 2,881

"코딩 에이전트를 위한 디자인 어휘"를 표방하는 도구로, `bolder`·`quieter`·`typeset` 같은 명령으로 UI를 조정하고 `critique`·`audit`으로 점수화된 리뷰를 받을 수 있습니다. 핵심은 LLM이나 API 키 없이 작동하는 62개의 결정론적 규칙 기반 탐지기로, 에이전트가 만든 UI에서 흔히 나타나는 "AI 티 나는" 디자인 패턴을 잡아냅니다. Anthropic의 `frontend-design` 스킬을 확장해 만들었다고 밝히고 있으며, 이미 트렌딩에 올랐던 hallmark(2026-07-13)와 비슷한 문제를 LLM 추론 대신 정적 규칙 엔진으로 접근한다는 점에서 비교해볼 만합니다.

## JetBrains/thinkrail

- <https://github.com/JetBrains/thinkrail>
- 언어: TypeScript
- 오늘 스타: 1,116

JetBrains가 공개한 인큐베이터 프로젝트로, `pi` 코딩 에이전트를 감싸는 에이전트 전용 IDE입니다. git worktree로 작업마다 독립된 워크스페이스를 만들어 여러 에이전트가 메인 체크아웃을 건드리지 않고 병렬로 작업하게 하고, 프로젝트 지식을 코드 옆에 두는 `SPEC.md` 그래프로 관리합니다. Bun 기반 호스트 서버가 `pi` 세션을 프로세스 안에서 실행하고, 타입이 있는 버전 관리 프로토콜로 React UI와 통신하는 구조입니다. "스펙과 코드를 같은 변경에서 함께 갱신한다"는 설계를 실제 제품 수준에서 구현한 사례로 참고할 만합니다.

## milind-soni/OpenMausBot

- <https://github.com/milind-soni/OpenMausBot>
- 언어: TypeScript
- 오늘 스타: 1,190

Claude, Codex, Grok 같은 기존 CLI 로그인을 그대로 활용해 여러 에이전트를 "연락처"처럼 채팅 앱에 등록해두고 쓰는 셀프 호스팅 오픈소스 프로젝트입니다. 서버 프로세스가 각 에이전트의 네이티브 프로토콜을 하나의 런타임 이벤트 스트림으로 정규화해 SSE로 UI에 전달하고, 위험한 작업 전에는 인라인 승인 카드를 띄웁니다. 클라우드 데스크톱이나 사용자 자신의 macOS/Ubuntu 컴퓨터 제어까지 옵트인으로 지원하는데, 여러 공급자의 에이전트를 하나의 이벤트 모델로 묶는 "하네스 서버" 설계가 멀티 에이전트 오케스트레이션을 공부할 때 참고가 됩니다.

벡터 검색(HNSW/IVF/Vamana 인덱스, 양자화, BM25 하이브리드 검색)과 서브마이크로초급 키-값 스토어를 하나의 Go 라이브러리/서버에 합친 프로젝트입니다. 샤드마다 Raft 복제를 두고 REST·gRPC·바이너리 TCP 세 가지 접근 경로를 제공하며, Linux/amd64용 AVX2 벡터 거리 연산 커널까지 손으로 작성했다고 밝히고 있습니다. `make test`/`make race`로 레이스 프리를 검증하고 MkDocs로 만든 문서 사이트까지 갖춰, 벡터 DB와 분산 합의(Raft)를 한 레포 안에서 같이 공부할 수 있는 드문 사례입니다.

### VoolFI71/go-arena

- <https://github.com/VoolFI71/go-arena>
- 언어: Go, 스타: 7, 생성일: 2026-02-01

Go의 GC 압박을 줄이기 위한 범프 포인터(bump-pointer) 아레나 할당자입니다. `New[T]`로 청크 내 커서를 전진시켜 할당하고, `Reset()`으로 메모리를 해제하지 않은 채 커서만 0으로 되돌려 재사용을 빠르게 하는 전형적인 아레나 할당 패턴을 그대로 보여줍니다. 아레나 포인터를 반환하거나 고루틴 간에 공유하면 안 된다는 안전 규칙을 README에 명시하고 `api_contract_test.go`로 공개 시그니처를 컴파일 타임에 검사하는 등, 저수준 메모리 관리 기법을 작은 코드베이스로 익히기 좋습니다.

### ericdrowell/brometal

- <https://github.com/ericdrowell/brometal>
- 언어: TypeScript, 스타: 107, 생성일: 2026-07-21

타입이 있는 TypeScript로 셰이더를 작성하면 빌드 시점에 WGSL로 컴파일해주는 WebGPU 툴킷입니다. 컴파일 파이프라인이 `TypeScript → Parser → Type Checker → GPU Semantic Analysis → GPU IR → 최적화 패스 → WGSL`로 명시적으로 나뉘어 있고, 속성 위치나 유니폼 업로드 같은 런타임 작업까지 컴파일 타임에 미리 결정해 런타임을 19KB(gzip 7KB) 수준으로 가볍게 유지합니다. Vitest로 컴파일러 골든 테스트를, 실제 GPU 위에서 Chrome·WebKit 픽셀 비교 테스트까지 돌리는 구성이어서, "작은 언어를 설계하고 실제 하드웨어 타깃으로 컴파일하기"를 끝까지 구현한 예로 공부할 가치가 있습니다.

### dweinstein/canary

- <https://github.com/dweinstein/canary>
- 언어: Go, 스타: 95, 생성일: 2026-03-24

macOS용 파일시스템 허니팟으로, `.env`나 `id_rsa` 같은 가짜 비밀 파일을 가상 마운트 지점에 깔아두고 접근이 발생하면 알림을 보냅니다. 기본 WebDAV 모드는 루트 권한 없이 Go 표준 `net/http`와 `mount_webdav`만으로 동작하고, NFS 모드는 FUSE 없이 NFSv3와 MOUNT 프로토콜(Sun RPC 프레이밍, XDR 직렬화)을 직접 구현해 같은 사용자 권한의 프로세스가 더 쉽게 찾거나 종료하지 못하게 만들었습니다. 서드파티 의존성 없이 약 1,400줄로 두 가지 파일시스템 프로토콜을 밑바닥부터 구현한 점이 네트워크 프로토콜과 보안 모니터링을 함께 공부하기에 적절합니다.

### NeverSight/NeverD

- <https://github.com/NeverSight/NeverD>
- 언어: C++, 스타: 99, 생성일: 2026-05-20

PE·ELF·Mach-O 네이티브 바이너리는 물론 EVM 바이트코드와 Solana SBF까지 다루는 바이너리 분석·디컴파일 엔진입니다. Capstone으로 명령어를 디코딩한 뒤 LowIR(아키텍처 중립 연산과 CFG) → MedIR(타입·호출 규약·SSA) → HighIR(구조화된 제어 흐름)로 올라가는 단계적 IR 파이프라인을 직접 설계했고, 리프터가 없는 명령어를 만나면 건너뛰지 않고 에러를 내는 strict 모드를 기본값으로 뒀습니다. `check-neverd` 테스트 타깃과 Unicorn을 이용한 시맨틱 테스트, 아키텍처/플러그인 가이드 문서까지 갖춰, 컴파일러 백엔드(LLVM)를 거꾸로 활용해 디컴파일러를 만드는 과정을 들여다보기 좋은 레포입니다.
