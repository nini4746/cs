외부 라이브러리 없이 C와 x86_64 어셈블리로 처음부터 짠 운영체제로, higher-half 커널, 4단계 페이징, 1000Hz 선점형 라운드로빈 스케줄러와 SMP를 갖췄습니다. 비트맵 물리 메모리 할당자와 copy-on-write fork를 지원하는 프로세스별 페이지 디렉터리, ramdisk VFS 위에 얹은 영속 EXT2 읽기/쓰기, ARP·IPv4·ICMP·DHCP·UDP와 완전한 TCP 상태 머신까지 구현한 네트워킹 스택, 32개 창을 다루는 더블 버퍼링 컴포지터까지 현대적 OS 스택을 거의 전부 손으로 짰습니다. 포팅한 TinyCC가 OS 내부에서 자기 자신을 컴파일하는 셀프 호스팅 단계까지 도달했고, 인커널 자체 테스트 배터리와 실제 UEFI 하드웨어 검증을 CI로 걸어둔 점에서 장난감 수준을 넘어선 프로젝트입니다.

### mochiOS/mochiOS

- <https://github.com/mochiOS/mochiOS>
- 언어: Perl(메타 레포 기준) · 스타: 64 · 생성일: 2026-01-12

"격리, 최소 권한, 복구 가능성"을 설계 원칙으로 내세운 하이브리드 커널 프로젝트로, 애플리케이션·서비스·드라이버를 서로 분리하고 꼭 필요한 권한만 부여하는 커패빌리티 기반 격리 모델을 지향합니다. AOSP처럼 `repo` 도구로 커널·시스템 서비스·애플리케이션 프레임워크 등 여러 하위 레포지토리를 하나의 소스 트리로 묶는 구조라 GitHub이 감지한 대표 언어는 매니페스트 비중 때문에 Perl로 뜨지만, 토픽에 명시된 대로 실제 구현은 Rust 하위 레포들에 나뉘어 있습니다. GitHub Actions 기반 CI와 별도 개발자 문서 사이트(developer.mochios.org)를 갖췄고 "아직 일상 사용에는 이르지 않다"고 스스로 밝히는 활발히 개발 중인 초기 단계 커널이라, 여러 하위 시스템을 아우르는 격리 설계를 어떻게 문서화하고 조직하는지 참고할 만합니다.

### f-rustrated/EastGuard

- <https://github.com/f-rustrated/EastGuard>
- 언어: Rust · 스타: 20 · 생성일: 2026-01-31

Kafka의 단일 컨트롤러 구조를 거부하고 메타데이터 합의, 장애 탐지, 데이터 저장, 복제를 서로 독립적으로 확장 가능한 서브시스템으로 쪼갠 "제로 컨트롤러" 메시징 시스템입니다. 여러 개의 작은 Raft 그룹이 토픽 일부씩을 나눠 맡는 DS-RSM으로 단일 컨트롤러 병목을 없애고, 장애 탐지는 중앙 하트비트 대신 SWIM 가십 프로토콜로, 복제는 ISR 대신 장애 시 세그먼트를 봉인하고 새 세그먼트를 여는 "seal-on-failure" 방식으로 단순화했습니다. Kafka·Pulsar와의 비교표, Mermaid 아키텍처 다이어그램, 각 설계 선택의 이유까지 문서에 촘촘히 담아둔 점에서, 분산 메시징 시스템을 처음부터 설계할 때 고려해야 할 트레이드오프를 공부하기 좋은 자료입니다.
