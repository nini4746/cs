## anthropics/claude-plugins-official

- 오늘 스타: 1,383 (총 41,302)

## MadsLorentzen/ai-job-search

- <https://github.com/MadsLorentzen/ai-job-search>
- 언어: Python
- 오늘 스타: 1,397 (총 49,541)

"내 컴퓨터에서 돌아가는 구직 활동"을 표방하며 오늘 가장 큰 폭으로 스타가 늘어난, 완전히 새로운 1위권 진입작입니다. `/setup`으로 문서·CV·인터뷰에서 프로필을 만들고, `/scrape`로 여러 구직 포털(Jobindex, LinkedIn 등)을 뒤져 매칭도 순으로 정렬하고, `/apply <url>`로 적합도를 평가해 CV와 커버레터를 작성한 뒤 별도 리뷰어 에이전트가 신선한 컨텍스트로 비평·수정하는 drafter-reviewer 패턴을 씁니다. 생성된 PDF는 LaTeX(moderncv/lualatex, 커스텀 `cover.cls`/xelatex)로 컴파일된 뒤 렌더링을 직접 확인하고 `pdftotext` 기반 ATS 적합성 체크까지 거치며, 채용 공고 본문은 "신뢰할 수 없는 입력"으로 간주해 가드레일이 샌드박스가 아닌 지시 수준 방어라는 점을 README가 스스로 명시합니다. 에이전트에게 실제 생계와 직결된 작업을 맡길 때 검증 단계를 어떻게 겹겹이 쌓는지 참고하기 좋은 사례입니다.

### vahmoh25/Veda

- <https://github.com/vahmoh25/Veda>
- 언어: Rust
- 스타: 80 (생성: 2026-10-03)

x86-64용 Rust 운영체제로, 캐퍼빌리티 기반 마이크로커널(`vkernel`)이 IPC·스케줄링·메모리 관리·SMP·틱리스 타이머를 담당하고 드라이버·파일시스템·윈도우 시스템·네트워킹은 모두 유저스페이스 서비스로 분리되어 있습니다. Veda가 자체적으로 지원하지 않는 하드웨어는 자체 하이퍼바이저 위에서 IOMMU로 격리된 Linux VM이 대신 구동하며, 서비스가 죽으면 `init`이 재시작하는 구조입니다. "Hey Veda"로 깨우는 음성 에이전트가 키보드·마우스와 같은 코드 경로로 100개 이상의 타입드 액션을 호출하되 위험한 동작은 데스크톱 셸의 승인을 기다리게 설계했고, 드라이버 크래시·케이블 분리·서비스 강제종료 같은 장애를 일부러 주입해 복구를 검증하는 테스트와 모의 Deepgram을 쓰는 오프라인 에이전트 테스트, 8개 이상의 아키텍처·개발 문서를 갖추고 있다는 점에서 완결성이 높습니다.

### ekmett/jam

- <https://github.com/ekmett/jam>
- 언어: C++
- 스타: 5 (생성: 2026-10-05)

Haskell `lens` 라이브러리 저자로 널리 알려진 Edward Kmett가 만든 C++26용 압축(compacting) 제너레이셔널 가비지 컬렉터입니다. 4바이트 포인터와 GC 헤더 없는 객체 레이아웃을 쓰고, `make_manifest`로 타입별 포인터 필드를 선언하거나 런타임 태그가 필요한 경우 trace hook을 직접 작성하는 방식으로 추적 대상을 명시합니다. 약한 참조·파이널라이저, old-to-young 쓰기 자동 추적, 멀티 워커 수집을 지원하고, HotSpot·GraalVM·Native Image용 런타임 통합까지 별도 모듈로 제공하며, 빌드·문서·커버리지(Codecov)·Docker·Nix 각각에 대한 CI와 SPDX 라이선스 헤더를 갖춘 점에서 실험적 장난감이 아니라 실제로 쓸 수 있도록 설계된 GC임을 보여줍니다.

### matrixarkai/matrixraft

- <https://github.com/matrixarkai/matrixraft>
- 언어: Rust
- 스타: 10 (생성: 2026-08-12)

OpenRaft에 의존하지 않는 독립적인 Raft 합의 크레이트로, "TemporalStore"라는 스토리지 런타임이 특정 리비전에 고정해 쓸 수 있는 재사용 가능한 Raft 기반층을 지향합니다. 읽기 안전성(read-index, lease read, bounded-stale read), 멤버십·러너 승격, append 안전성, WAL, 스냅샷, 전송 검증을 모듈별로 분리하고, 프로덕션 준비 상태를 `blocked`/`feature_correct`/`production_ready`로 명시하며 실제 장애 주입 증거와 C++ BaselineRaft 벤치마크와의 성능 동등성을 요구하는 "fail-closed" 게이트를 두고 있습니다. README가 아직 연결되지 않은 드라이버-런타임 배선이나 동작하지 않는 설정값 3개를 스스로 명시하는 등 한계를 솔직히 공개하는 태도가, 과장 없이 신뢰할 만한 프로젝트라는 인상을 줍니다.
